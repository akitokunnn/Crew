# Crew 顶部交互原型

双击 **`start-demo.cmd`**，或直接打开 **`index.html`**。

要直接体验已选的 **B · 侧栏即导航，36 项任务**，双击 **`sidebar-many.html`**。也可从方案总览进入 B；上方“试用工具”可在 **3 项／36 项任务**之间切换。

不需要安装依赖或启动服务。这里是离线界面原型，不连接正式 Crew、不调用 AI；发送消息和“开始推进”只改变本地演示状态。请保留目录内文件的相对位置。

四个方案共用任务样例与字体，主要比较信息架构，方便判断顶部能否更干净、常用操作是否仍然好找。B 默认打开 36 项任务，其余入口保留原来的 3 项场景。

## 四个方案

| 方案 | 信息放在哪里 | 适合什么情况 | 需要付出的代价 |
| --- | --- | --- | --- |
| **A · 单行上下文切换** | 当前会话与任务合成一条上下文栏，点同一处切总会话或任务，长说明放详情 | 希望顶部安静，同时保留明确的当前位置 | 切任务需要先打开选择器 |
| **B · 侧栏即导航（已选方向）** | 当前 leader 下直接列总会话和任务；搜索、状态筛选与可折叠分组组织 36 项任务 | 经常在多个并行任务间来回切换，也要快速找到等待自己拍板的任务 | 占用侧栏空间；小屏需要展开导航抽屉 |
| **C · 任务扉页** | 完整任务标题、状态和启动说明进入可滚动正文；顶部保留轻量工具栏 | 想先读清任务，再长时间看对话 | 初次进入会先看到任务说明；滚动后需要通过短标题辨认上下文 |
| **D · 会话页签** | 总会话和任务像打开的文档一样排列成页签 | 经常在少数几个任务间快速切换 | 页签多或名称长时会拥挤，需要滚动或使用任务选择入口 |

当前优先试 **B**：这是已选定的方向，任务切换始终在左侧，顶部只保留当前内容。36 项任务用来观察任务变多后的查找、分组与滚动；A、C、D 仍保留作对照。

## B 的 36 项任务场景

36 项任务涵盖舱体动作、NPU 推理、音频前处理、延迟测量和实机回放。初始状态为 **6 项待拍板、8 项推进中、10 项待规划、12 项已交付**，名称长短混合，可检查拥挤时的可读性。

- **搜索**：按完整任务名称查找，例如输入“静音”“时钟”或“NPU”。
- **状态筛选**：先只看待拍板或推进中，减少同时浏览的任务数量。
- **分组折叠**：收起暂时不看的状态组，再展开需要的任务。
- **任务区独立滚动**：滚动长列表时，项目入口、总会话与底部全局助手／设置仍有固定位置；聊天区域单独阅读。

切换任务仍分别保留草稿与对话。36 项场景里的任务与状态都是本地示例，用来观察侧栏承载大量任务时的体验。

## 五分钟试用

1. **第 1 分钟：试切换和草稿。** 从 B 的 36 项任务开始，在当前任务输入一段草稿，不发送；切到第二个任务，再返回，确认草稿仍在。进入总会话写另一段草稿，再回任务，感受两种会话是否容易区分。
2. **第 2 分钟：试开始任务。** 在“试用工具”选 `queued`（待规划），点击页面里的“开始推进”。观察状态变化、启动说明的去向，以及对话输入区是否仍然显眼。发送一条消息也只会在原型内模拟。
3. **第 3 分钟：试查找与待拍板。** 在侧栏只看待拍板，搜索“静音”并进入结果，找到处理入口；清空搜索、恢复全部状态，折叠已交付组，再滚动到列表较后的任务。观察是否仍能方便地回总会话。
4. **第 4 分钟：试长标题和窄窗。** 开启“超长标题”，将浏览器收窄，打开详情读完整标题。需要精确测手机宽度时，可在 Chrome／Edge 按 `F12`，再按 `Ctrl+Shift+M`，把宽度设为 **390px**。检查任务切换、状态、详情和输入区是否仍然可用。
5. **第 5 分钟：对比任务数量与其他方案。** 用“试用工具”切换 3 项／36 项任务，比较侧栏密度；也可到 A、C、D 各做一次换任务。收起工具，专看实际页面；需要时从底部入口恢复。记下 B 在任务很多时最碍事的一处。

“试用工具”还可切换深浅色。它是原型的比较工具，不属于拟议的 Crew 顶栏。

比较时可只回答四个问题：**我在哪个会话？怎么换任务？现在需要我做什么？完整信息去哪看？** 顶部变短的同时，这四个问题仍应容易回答。

## 参考思想与 Crew 的推导

参考的是成熟产品如何安排信息，而非复制其视觉皮肤：

- [VS Code · Breadcrumbs](https://code.visualstudio.com/docs/editing/editingevolved#_breadcrumbs)：把当前位置与相邻对象的切换结合起来。A 将这个思想用于 Crew 的总会话／任务上下文。
- [Slack · 快速使用指南](https://slack.com/help/articles/360059928654-How-to-use-Slack--your-quick-start-guide)：会话标题可以承载进入详情的入口，长描述不必一直展开。原型据此把 leader 的完整职责与低频信息放进详情。
- [Linear · Project details sidebar](https://linear.app/docs/projects#project-details-sidebar)：属性与详情可以进入按需打开的侧栏，不必全部常驻在内容上方。
- [Primer · Navigation](https://primer.style/product/ui-patterns/navigation/) 与 [Progressive disclosure](https://primer.style/product/ui-patterns/progressive-disclosure/)：保持稳定的导航位置，同时按需要展开次要信息。B 的会话树与各版详情入口借鉴了这两点。
- [VS Code · User interface](https://code.visualstudio.com/docs/editing/getting-started/userinterface)：页签适合在已打开的工作对象间快速切换，D 用它探索少量并行任务的操作节奏。

**C 的“任务扉页”是针对 Crew 的设计推导**：把一次性阅读的任务背景放回正文，减少固定工具栏的负担；不是声称 Linear 或上述项目原样提供了同一页面。

这些是供选择的原型，尚未替换正式 Crew 的交互。

## 验证与打包

本轮已重跑 3 项任务对照场景：真实 Chrome 检查四版 × 1440／768／390px，共 12 组交互旅程、531 个断言，覆盖独立草稿、切换不启动、显式启动与发送、状态与拍板、长标题详情、模式保存、刷新持久化、笔记下载、多窗口比较、深浅色及键盘焦点。

B 的 36 项任务场景另通过 267 个断言，覆盖 1440×900、1024×600 和 390×844：任务独立滚动、固定入口、搜索保焦点、完整标题搜索、筛选计数、分组折叠、定位当前任务、草稿与滚动位置、状态同步及 3／36 项切换。浏览器错误、外网与 API 请求均为零。另已实拍核对 390×600 短屏；选中任务可完整定位到分组标题下方。图库 B 缩略图已更新为 36 项实际页面。

验证脚本为 `smoke.cjs`，使用可用的 Playwright 和本机 Chrome，运行 `node prototypes/header-lab/smoke.cjs`。证据写入仓库 `Temp/header-lab-review/`，不访问正式 Crew。

多任务验证运行 `node prototypes/header-lab/smoke-many.cjs`，证据在 `Temp/sidebar-many-review/`。

源码直接打开时复用仓库里的字体与图标。若要拷贝到其他位置，请在 PowerShell 运行 `./prototypes/header-lab/package.ps1 -OutputRoot <新的输出目录>`；它会打成含字体与授权文件的独立 ZIP。解压后双击最外层 `start-demo.cmd` 即可，无需 Node、Python 或服务。输出目录已有同名文件时脚本会停止，避免覆盖旧试用记录。
