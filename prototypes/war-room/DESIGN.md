## 3. 尺寸

- 页头 56px（≤760：60px；≤620：两行约 64px）。标题 15px/600，副行 12px。操作按钮 30px 高（≤760：36px）。
- 参战栏：成员卡两行网格（头像 34px | 名字行 / 状态行 | 上下文环 / 暂停·接管），卡高约 54px，卡间距 8px，三张等分 + 72px“邀请”虚线格。≤760 每张固定 262px 横向滚动；≤620 变紧凑头像列（头像 38px + 名字 + 短状态，每格 ≥72px，整格可点）。
- 时间线内容最大宽 860px，左右 20px（≤760：16px）。发言头像 28px；交接节点、折叠组、拍板卡左缩进 38px（对齐发言正文），≤620 取消缩进。
- 交接节点细条最小高 30px，字 12.5px；阻塞节点上下多 3px 内边距。
- 拍板卡：圆角 14px，问题 15px/600（≤760：16px），选项沿用 `.opt`（≤760 最小高 48px）。
- 右面板 320px；状态板每项约 46px（有原因两行），组标题 26px；契约等宽 11.5px（≤760：12.5px），默认收起到 118px 渐隐，“展开全部”。
- 可点热区：投递徽章沿用交流区（视觉 26px、热区 32px）；成员卡小按钮 24px + 透明热区上下各 4px（`pointer:coarse` 时 30px）；底部单按钮 44px。

| | 待你答复 | 已答复 |
| --- | --- | --- |

| 状态胶囊 | 沙漏图标 + “待你答复” | 勾 + “已答复” |
| 内容 | 问题、分歧说明、选项（推荐项青边 + “推荐”）、推荐理由、自由答复框、成员意见（头像 + 选项字母） | 问题（降为 14px/500）、“你选了 B · …”答复条（时间 + 选项说明）、“其余 N 个选项已收起 · 答复已回到牵头，由它在房里收口” |

右面板“拍板卡”摘要同两态：待答复行琥珀边底 + “待你答复”，已答复行显示所选字母；点击跳到时间线里的卡片并闪一下。

### 4.4 交接节点与细碎事件

- 交接节点 = 状态板 / 契约变化，单行细条：状态图标 + 小头像 + “某某 把「事项」标为 [记号] 原因” + 时间 + “在状态板看”（点了右面板对应项高亮）。
- 阻塞节点额外：琥珀底、琥珀边、左 3px 实线，原因加粗琥珀字——时间线里扫一眼就能看到卡点。
- 契约变化：花括号图标 + “看改动”（展开右面板契约）。
- 开房 / 收尾等系统事件：同样细条，图标为房间 / 完成。
- 细碎事件默认折叠为一个虚线按钮“3 条状态变化 · 支付 新增 5 项任务 等”，展开后是左侧虚线引导的节点列表。规则建议：连续 ≥2 条非阻塞的状态变化合并折叠；阻塞、契约变化、拍板卡永不折叠。

### 4.5 投递徽章

完全沿用交流区 `cx-dl`：排队（虚线）/ 排队 N 分钟（琥珀实线，≥10 分钟）/ 已送达（蓝）/ 已回复（青）；右侧聊天小按钮 = 打开对方私聊。`@所有成员` 的发言组标签写“点名全体”。点名候选只有成员，按钮带在线状态点和“在跑 / 外部窗口 / 已暂停”小字，提示点名后多久送达。

## 6. 无障碍

- 对比度（脚本按变量实算，浅 / 深）：正文 13.5 / 12.2；`--wr-muted` 5.5 / 6.0；阻塞字 / 阻塞底 4.95 / 6.6；进行中字 / 底 4.95 / 6.7；完成字 / 底 5.8 / 5.8；在跑字 5.3 / 5.8；Codex 标签 5.9 / 5.2。全部 ≥ 4.5。
- 状态都有文字 + 形状（见 §4），色弱下仍可区分；阻塞、待答复另有框型 / 底色 / 左边条。
- 语义：`main` 用标题 `aria-labelledby`；参战栏 `section[aria-label=参战成员]`；时间线滚动区可聚焦并有 `aria-label`；交接节点 `role=note` + “状态变化：阻塞”之类的 `aria-label`；拍板卡 `section[aria-labelledby=问题]`，选项 `role=group`；右面板 `aside`，窄屏抽屉 / 底部单有关闭按钮，Esc 关闭，打开时焦点移到关闭按钮。
- 只剩图标的按钮都有 `aria-label`（“暂停 语音”“接管 语音：打开它的私聊”“发拍板卡（请牵头汇总）”等）；成员卡在 ≤620 整格是一个按钮，读出“语音，Codex，外部窗口，正在做：SDK 签名适配。点开看详情”。
- 投递徽章沿用交流区的 `aria-label`（“点名 语音：排队 14 分钟。点开看说明”）。上下文环 `role=img` + “上下文已用 71%，快满了”。
- `prefers-reduced-motion`：在跑脉冲停在静止光圈、抽屉无过渡、状态板定位高亮改为静态描边、折叠箭头无动画；交流区原有的 `cx-flash` 降级照旧。

## 8. 与设计文档的出入 / 待定

1. **“发拍板卡”由谁发**：§6 规定 `war_room.decide` 只有牵头能调，但界面是用户在看。原型保留“发拍板卡”按钮，点了在发言框预填“@支付 把还没定的事汇成一张拍板卡给我”并点名牵头，按钮 title 说明原因。若要用户能直接发卡，需要后端放开权限。
2. **用户开房时的牵头**：§6 说“开房者为牵头”，但用户不是 Leader。入口小样的升级表单里成员胶囊带“牵头”标，需要能选；建议 `war_room.open` 支持 `lead`。
3. **拍板卡的“成员意见”**：现有 `decisions` 没有逐人意见，原型用“支付 A · 前端 A · 语音 B”。需要后端给（见交付清单）。
4. 细碎事件的折叠规则（§4.4）是视觉稿建议，未写进设计文档。
