# Crew 对话与组织架构原型

演示一个 leader 同时推进多个任务、同一组员参与多个任务时，聊天界面和右侧组织架构怎么表达。所有人物、任务、分工和对话都是样例数据。

用 Edge 或 Chrome 直接打开 [index.html](index.html)，不需要安装依赖，也不需要启动服务。左上角下拉可以切换到第二组（见川）和空组（守望）。

## 设计取舍

- **leader 是任务的主人，不是任务成员。** 后端 `goals.create()` 会自动给 leader 写入一条分工，内容是原始需求，因为执行记录必须挂在分工上。这只是为了复用执行机制，后端不需要改。投影层把这条分工当作主责，组员按「全部分工 − leader」计算。
- **只有 leader 有总会话。** 每个任务行就是 leader 在这个任务里的对话，组员的对话都属于某个任务。待命组员没有对话入口，派活后才出现在对应任务下面。
- **当前对话归属只在两处出现：** 标题首行的「人员 / 任务」，以及输入框里的占位提示「发给 人员 · 任务」。
- **右栏是一层树。**
  - 标题写「林序组」，旁边是总会话入口。
  - 任务行的状态图标作为节点，用圆角折线连接组员。
  - 连线平时是浅灰色。当前对话所在的路径，或者选中组员的所有分支，会改用主色，其余行变淡。
  - 收起的任务显示为一行「状态 · 参与者姓名」。
- **组员行显示四样信息：** 姓名、跨任务数（层叠图标加数字）、执行状态、本任务分工。点击组员会在行内展开他的各任务对话入口，执行载体只在这里显示。
- **完整图谱分左中右三列：** leader、任务、组员。
  - 每个组员只出现一次，多任务关系用曲线表达。
  - leader 到任务的线是统一的细线。组员连线中，实线表示已有执行记录，虚线表示已分配但还没启动。
  - 悬停或点击会点亮相关连线。聚焦任务时，组员副标题显示他在该任务的分工；聚焦组员时，任务副标题显示他的分工。
- **图标统一为 24 网格、1.6 线宽的线性图标。** 状态主要靠形状区分，颜色只是辅助：
  - 实心点：执行中
  - 时钟：排队
  - 叹号：等你答复
  - 双竖线：暂停
  - 横线：待继续
  - 虚线环：未启动
  - 对勾：完成
- **草稿和阅读位置按 `(personId, taskId)` 分开保存。** 有草稿的对话会在导航和树里显示铅笔标记。进入过的组员对话会挂在导航中对应任务下面。

## 样例覆盖

- **林序组：** 6 位组员，4 项当前任务和 1 项已完成任务。
  - 知衡和听澜各参与两项任务。
  - 青禾在待命，砚川只有历史参与。
  - 时雨在原任务里的分工已经交接。
- **任务状态：** 推进中、等你答复、已暂停、排队中。暂停的任务只能查看，不能输入。
- **见川组：** 序白已分配，但还没有执行记录。
- **守望组：** 没有组员，也没有任务。

## 接入依据

后端已经有多对多关系。`goals.get()` 和 `goal_api.card()` 返回 `assignments`，工作区快照里的 `goals` 也已包含这些分工；任务详情提供 `executions`。`data.js` 模拟这些原生字段，`model.js` 负责投影：

1. 当前执行的匹配规则：按 `goal_id`、`session_id`、本轮 `round` 和本要求版本 `requirement_version` 匹配，再取最新的 `generation`。
2. 已释放（`released`）的分工，以及已结束（`completed / failed / cancelled`）的任务，都算历史参与，默认隐藏。
3. 真实接入时，分工关系可以直接取自工作区快照。要拿到精确的执行状态，需要合并任务详情里的执行记录，或者给快照补上同样的投影。
