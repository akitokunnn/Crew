# Crew 组织架构交互方案

2026-11-04。三种展示共用同一组样例，帮助比较一个 leader 多任务时的成员归属表达。所有人物、任务、分工与对话内容均为样例。

## 打开与比较

直接用 Edge 或 Chrome 打开本目录的 [index.html](index.html)，无需安装依赖或启动服务。顶部可切换三个版本，负责人下拉可以查看第二组与空组。

| 方案 | 首先回答的问题 | 可以操作的内容 |
| --- | --- | --- |
| 任务分组 | 每个任务谁在做什么 | 展开或收起分工，点击任务、成员，查看跨任务关系 |
| 成员矩阵 | 每个人关联哪些任务 | 按行对照分工，点击交叉格查看指定任务中的成员，窄屏固定人员列并局部横向滚动 |
| 关系图谱 | leader、任务、成员如何连接 | 展开分支，点击成员后关闭详情，同一个人在所有任务中一起高亮 |

三个版本都能搜索任务名称、编号或成员，筛选任务状态，开关历史参与，进入成员详情、任务对话预览与总会话预览。任务内对话显式保留任务编号，总会话的任务作用域为 `null`。没有执行记录的分工显示“已分配 · 未启动”，对话预览显示尚无执行记录。

桌面任务分组采用双列成员，1100px 以下改为单列。浅色与深色跟随系统，减少动态效果跟随系统偏好。浏览器只保存本原型的版本、负责人和筛选偏好，键名前缀为 `crew-org-task-lab-`。

## 样例覆盖

- 林序组包含 6 位成员、4 项当前任务与 1 项已完成任务。知衡和听澜分别关联两项当前任务。
- 林序统筹所有本组任务，同时在组织架构任务中亲自执行。
- 任务有推进中、等你答复、已暂停、排队中和已完成状态。人员执行状态独立显示。
- 青禾当前待命，砚川只有历史参与。时雨在原任务中的分工已经交接。
- 时雨的历史执行使用 Codex，当前总会话使用 CC。任务节点、交叉格和任务对话使用执行记录的载体，矩阵行头保留人员当前载体。
- 见川组混合 CC 与 Codex，序白已分配但尚未产生执行记录。守望组没有成员和任务。
- 任务名称包含长中文，样例执行包含旧要求、旧轮次和失败后新一代执行。

## 后端盘点与接入依据

源码基线为 `rebuild/v2` 的 `d379671`，桌面 `package.json` 为 `0.3.7`。产品分支约定要求新版工作合入 `rebuild/v2`。

现有后端已经提供多对多关系。`goals.get()` 与 `goal_api.card()` 返回 `assignments`，工作区快照的 `goals` 已包含这些分工。任务详情提供 `executions` 与 `work_items`。目前正式组织图的 `renderRight()` / `memberNode()` 只展示 leader 与直属成员及全局任务文案，缺少按任务呈现分工。

本演示的 `data.js` 模拟原生人员、目标、分工和执行字段，`model.js` 生成三个视图共用的投影。

1. 当前执行按 `goal_id`、`session_id`、本轮 `round`、本要求版本 `requirement_version` 匹配，再选最新 `generation`。
2. `released` 分工以及 `completed / failed / cancelled` 任务属于历史参与，默认隐藏。
3. leader 默认 assignment 表达任务负责关系。图中的任务节点始终标记其统筹身份，有独立执行记录时再进入执行人员列表。
4. `active_goal_ids` 可以包含暂停或等待任务。当前关联数按分工计算，执行状态从独立执行记录投影。
5. 真实接入时，工作区快照可直接提供分工关系。精确执行状态需要组合任务详情中的执行记录，或给快照补充同一投影。

该交付覆盖独立设计演示。真实后台接口接入、运行状态刷新、正式桌面内嵌与原生 AI 操作仍需在选定展示方式后验收。

## 对话右侧的架构图

用户选中关系图谱后，补充聊天中的窄面板版本，源码基于 `dee88f8`。打开 [chat.html](chat.html)，或从原演示页右上的“对话右侧架构”进入。该页面共用原样例、任务关系投影、头像、状态与完整关系图谱。

聊天第一排直接显示“人员 / 任务名称”或“人员 / 总会话”。任务切换从左侧导航和右侧架构图进入。

右侧列默认宽 332px。当前任务展开，其余任务收起时保留参与者姓名。成员显示该任务的工作、执行状态和载体，同时标明关联的其他任务。顶部可切换“本任务”与“全组任务”，也可展开完整图谱。选择成员先显示分工，点击“本任务对话”或“本人总会话”再切换聊天。“正在聊”按人员与任务共同定位。

对话、草稿、样例消息和阅读位置按 `(personId, taskId)` 分开保留。浏览架构、选择成员、展开与返回完整图谱均保留原对话。暂停任务为查阅状态，未启动的成员显示尚无执行记录。消息只在演示中本地保存，页面刷新后清空。

## 对话架构轻量版

2026-11-04 评审后新增 [chat-light.html](chat-light.html)，与 `chat.html` 共用 `data.js`、`model.js`，可从原演示页右上的“轻量版”进入，页内“对照原版”可来回比较。

原版的臃肿主要来自三处：归属信息重复（导航、标题、输入框标签、右栏“当前对话”和“正在聊”）、框线叠框线（leader 卡片、任务卡片、独立的“对话 ↗”列、全宽分段控件、底部常驻详情抽屉），以及连线不连节点、完整图谱里成员按任务重复出现。轻量版的取舍：

- leader 是任务的主人，不是任务成员。后端 `goals.create()` 会给 leader 自动写入一条分工（内容为原始需求），因为执行记录必须挂在分工上；这只是为了复用执行机制，后端不需要改。投影层把这条分工当作主责，组员按「分工 − leader」计算。右栏不再以 leader 作树根，标题写「林序组」，旁边是总会话入口；第一层是任务（每个任务行就是 leader 的任务对话），第二层是组员。
- 只有 leader 有总会话。组员的对话都属于某个任务，详情里只列各任务对话。待命组员没有对话入口，派活后才出现在对应任务下面。
- 归属只在两处出现：标题首行“人员 / 任务”，以及输入框占位“发给 人员 · 任务”。去掉输入框上方的标签和右栏的“当前对话”文字。
- 右栏不再画卡片。任务行的状态图标作为节点，用圆角折线连接组员。平时连线为浅灰；当前对话路径或选中成员的所有分支着主色，其余行变淡。收起的任务一行显示“状态 · 参与者姓名”，选中的人在姓名中标出。
- 去掉“本任务 / 全组任务”切换。任务可以逐项折叠，跨任务关系始终可见。
- 组员行显示姓名、跨任务数（层叠图标加数字）、执行状态和本任务分工，载体只放在展开详情里。点组员在行内展开其各任务对话（附分工与载体），悬停时显示直达本任务对话的按钮。
- 完整图谱改为左中右三列：leader、任务、成员。每个成员只出现一次，多任务关系用曲线表达。leader 到任务统一为细线；组员连线中，实线表示有执行记录，虚线表示已分配未启动。悬停或点击时点亮相关连线；聚焦任务时成员副标题显示该任务分工，聚焦成员时任务副标题显示其分工。
- 图标统一为 24 网格、1.6 线宽的线性图标。状态靠形状区分（实心点：执行中，时钟：排队，叹号：等你答复，双竖线：暂停，横线：待继续，虚线环：未启动，对勾：完成），颜色只作辅助。
- 草稿和阅读位置继续按 `(personId, taskId)` 分开保存。有草稿的对话会在导航和树里显示铅笔标记；进入过的组员对话挂在导航对应任务下面。

```powershell

node prototypes/org-task-lab/chat-light-smoke.cjs
```

浏览器验证在 1440、1024、390px 下覆盖草稿与阅读位置、跨任务高亮与入口、暂停只读、完整图谱聚焦与跳转、空组，共 15 项通过，控制台错误 0。截图位于 `Temp/org-qa/chat-light-browser/`。其中阅读位置恢复只在 1024×640 下实际滚动验证，另外两个尺寸的样例对话不足一屏。
