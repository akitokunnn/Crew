# 想法思维导图设计（R3）

> 日期：2026-11-27 · 分支 `claude/mindmap`（基于 `claude/spatial-studio-ui` `9a2cc6f`）
> 关联：[总计划 R3](REBUILD_PLAN_2026-11-27.md)、[新手引导与 Teamwork 设计](ONBOARDING_AND_TEAMWORK_DESIGN.md)（导图是助手开局作战的输入草图）、[交互清单](INTERACTION_INVENTORY.md)“想法墙”“架构图”两节

想法页在“卡片墙”之外增加“导图”形态：想法拖进导图成为节点，节点之间建父子关系、折叠展开；选中若干分支，一键预览并转换成某个工作区的架构图（`domains` / `domain_leaders`），可以分批转。卡片墙的快速记想法、标签、回顾、去聊聊、转任务、合并、暂缓、归档、多选批量等能力全部保留，导图只新增一种看法和一组结构操作。

## 1. 数据模型

导图是个人数据，和想法同属 HOME 级个人区（想法本身可以是全局或属于某个工作区）。一个 HOME 只有**一张导图画布**，画布上可以有多棵树（多个根），用折叠管理规模。第一版不做“多张导图”。

### 1.1 新表（`plugin/crew/mindmap.py` 的 `ensure_schema`，只新增、不改旧表）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `personal_mindmap` | `singleton`（=1）、`version`、`updated_at` | 整张导图的版本号。每批编辑 +1；页面带 `base_version` 提交，过期就 409，先刷新再改，与架构图的 `domain_boards.version` 同一套做法 |
| `personal_mindmap_nodes` | `id`、`parent_id`（自引用，NULL=根）、`note_id`（UNIQUE，引用 `personal_notes`）、`label`、`sort_order`、`collapsed`、`created_at`、`updated_at` | 节点二选一：**想法节点**（`note_id`）或**主题节点**（`label`，纯文字分组，比如“手机端”）。`CHECK((note_id IS NULL) <> (label IS NULL))` |
| `personal_mindmap_links` | `node_id`、`project`、`domain_id`、`converted_at`，主键 `(node_id, project)` | 节点已转成哪个工作区的哪个 part。`domain_id` **不设外键**：架构图里删 part 不能被导图挡住；读取时只认架构图里仍存在的 part，失效的链接等同“没转过”，下次转换覆盖 |

### 1.2 与想法的关系

- 想法节点**引用**想法，不复制内容：标题、标签、阶段、沉睡、归档状态都实时取自想法。改想法（编辑、打标签、合并……）导图自动跟着变。
- 一条想法最多出现在导图上一次（`note_id` UNIQUE）。没上图的想法出现在导图左侧“未上图”托盘。
- 想法从不被删除（现有代码只有归档），所以外键安全。归档、已转任务、已并入的想法节点仍留在导图上，显示为淡化并带状态说明；需要时手动移出。
- 从导图**移出**节点只删节点，不动想法；它的子节点上移一级、占据它原来的位置（与架构图删 part 同一规则），不会连带丢失。

### 1.3 编辑操作（`POST` 一批 `ops`，同一事务，任一步无效整批拒绝）

| op | 参数 | 规则 |
| --- | --- | --- |
| `create` | `id?`、`parent_id`、`index?`、`note_id` 或 `label` | 想法必须存在且未上图；`label` 1–40 字；`index` 缺省追加到末尾 |
| `label` | `id`、`label` | 只用于主题节点；想法节点改名走想法“编辑” |
| `move` | `id`、`parent_id`、`index` | 改挂与同级排序共用；不能挂到自己或自己的后代下 |
| `collapse` | `id`、`collapsed` | 折叠状态随导图保存 |
| `remove` | `id` | 子节点上移一级；删除该节点的转换链接 |

返回 `{map, effects}`，`effects[i]` 说明第 i 步的副作用（新 id、被上移的子节点），页面据此做“撤销移出”。

### 1.4 迁移

全部是 `CREATE TABLE IF NOT EXISTS`，首次读写导图时建表；不改 `schema.sql` 里的核心表，也不改 `personal_notes`。旧 HOME 打开导图得到空画布，所有想法都在托盘里。`domains.apply` 拆出不开事务的 `apply_ops`，供转换在同一事务里写架构图与链接；`apply` 行为不变。

## 2. 交互

### 2.1 入口与布局

- 想法页标题栏加分段开关 **卡片墙 | 导图**，状态写进地址 `#layout=map`（只改 hash，不带 query，遵守 `/notes.html` 不带 `?` 的桌面路由契约）。
- 导图形态下，快速记想法输入框和筛选栏照旧；右侧标签栏在宽屏上也像窄屏那样收起，把宽度让给画布（1280 下画布从约 690px 变为约 930px），状态视图下拉出现在筛选栏、“管理标签”按钮出现在标题栏，与现有窄屏做法一致。中间区域换成 **托盘 + 画布**：
  - 托盘“未上图”：当前筛选（标签 / 工作区 / 状态视图 / 排序）下、还没上图的想法，紧凑卡片。可拖进画布；每张卡片有常驻“上图”按钮（挂到当前选中节点下，没选中就成为新根），触屏也点得到。
  - 画布：从左到右的思维导图，节点是 Studio 小卡片，左侧色条标识所属一级分支，连线是中性色圆角肘线；点阵底纹与架构图一致。原生滚动平移（触屏单指拖动即可），`Ctrl/⌘ + 滚轮` 与右下角 `− 100% +` 缩放。
  - 筛选不匹配的想法节点淡化而不是消失，结构保持完整；主题节点不受筛选影响。
- 选中节点后画布底部出现操作条：子主题、同级、折叠/展开、改名（主题）或编辑（想法）、上移、下移、升级、降级、移出；想法节点另有 去聊聊、转任务、⋯（复用卡片墙的同一份菜单：编辑、置顶、打标签、合并、暂缓、归档、最初记录、讨论结论）。宽屏上四个移动按钮只显示图标（提示与读屏名写明名称和快捷键）；手机上操作条是图标 + 短字的网格，所有操作同时可见，不藏在横向滚动里。

### 2.2 新建节点

- 画布顶部“＋ 主题”新建根主题；选中节点后按 `Tab`（或 `Insert`）建子主题、`Enter` 建同级主题——先出现一个就地输入框，`Enter` 才真正提交，`Esc` 放弃，不会留下空节点。
- 快速记想法：导图形态下若选中了节点，输入框下方提示“记下后挂到「X」下 ×”，记下的想法直接成为该节点的子节点；点 × 只记不上图。没选中节点时，新想法进托盘。

### 2.3 拖拽挂接（鼠标 / 触控笔）

- 托盘卡片拖到节点上：节点中部 = 挂为子节点；节点上沿 / 下沿 = 插到它前面 / 后面成为同级；拖到空白处 = 成为新根。
- 画布节点同样可拖：改挂、调序、拖到空白变根；拖回托盘 = 移出导图。落点有高亮和“挂到「X」下 / 插到「X」前”文字提示。拖到自己的后代上不可落，显示禁止提示。
- 触屏手指拖动用于平移画布，结构操作走操作条（升级 / 降级 / 上移 / 下移）与托盘“上图”按钮，功能不缺。

### 2.4 折叠展开

- 有子节点的节点右缘有折叠钮（压在连线起点上）：展开时悬停、选中或触屏下显示 `−`，折叠后常显 `+N`（N = 隐藏的后代数）。点折叠钮、键盘 `Space`、操作条都可以折叠展开。折叠状态随导图保存。

### 2.5 键盘（焦点在画布内时）

| 键 | 作用 |
| --- | --- |
| `←` `→` `↑` `↓` | 到父节点 / 第一个子节点 / 上一个、下一个同级 |
| `Tab` / `Insert`、`Enter` | 新建子主题、同级主题（就地输入） |
| `F2`、双击 | 主题改名；想法打开“编辑想法” |
| `Space` | 折叠 / 展开 |
| `Alt + ↑ ↓` | 同级上移、下移 |
| `Alt + ←`、`Alt + →` | 升级（挂到祖父节点、排在原父节点之后）、降级（挂到上一个同级下） |
| `Delete` / `Backspace` | 移出导图（提示可撤销） |
| `Esc` | 取消拖拽 / 输入，取消选中并把焦点交回画布容器，之后 `Tab` 可正常离开画布 |
| `=` `-` `0` | 放大、缩小、100% |

页面级快捷键保持：`R` 回顾、`T` 打标签（选中想法节点时作用于它）、`1–9` 置顶标签（同样作用于选中的想法节点）。

### 2.6 与现有能力的关系（全部保留）

| 能力 | 导图形态下 |
| --- | --- |

## 3. 转换规则（导图 → 架构图）

### 3.1 选择

点“转成架构图”进入选择状态：点节点勾选一个**分支**（该节点连同全部后代，包括折叠起来的）；可勾多个分支，祖先已勾时后代自动算在内。选择栏显示分支数与节点数，选目标工作区后“预览改动”。

### 3.2 节点 → part

- 每个节点对应一个 part；名称取主题文字或想法标题，压成单行、超过 40 字截断（架构图名称上限），预览里可逐个改。
- 层级照搬：节点的父节点对应的 part 就是新 part 的父 part。
- **分支的顶**挂在哪：若它的导图父节点**以前已转进同一工作区**（链接仍有效），自动挂到那个 part 下（分批转换的连续性）；否则挂到预览顶部所选的“挂到”位置（顶层或任一现有 part）。
- 已经转过（链接有效）的节点不再新建，标“已转”，其子节点照常挂在它对应的 part 下。
- “跳过”的节点不建 part，它的子节点上移挂到它的上级。
- 新 part 的位置放在现有架构图包围盒外侧（上→下方向放右边，左→右方向放下边），不压住已有节点；转换后提示可在架构图点“自动排列”。

### 3.3 哪些节点挂 Leader

- 只放**本工作区已有的 leader**；新建 leader 属于助手开局作战（阶段四），转换不启动任何模型。
- 自动建议：想法已“转任务”且那次新建的 leader 讨论就在目标工作区、仍是 leader → 预选这位 leader 放进该节点的 part。
- 叶子节点标“建议挂 Leader”，其余由用户在预览里从下拉框选择；一位 leader 在一次转换里只能放进一个 part。
- leader 原来在别的 part：改后图标“从「原 part」移来”，原 part 的负责人标记随之取消（架构图既有规则）。

### 3.4 冲突处理

| 情况 | 处理 |
| --- | --- |
| 目标位置已有同名 part（且没被别的节点链接） | 标“同名”，默认**并入已有 part**（只建链接，不新建）；可改为“仍新建”或“跳过” |
| 节点已转过，但架构图里那个 part 被改名或挪走 | 视为已转，保留架构图里的现状，改后图显示当前名称 |
| 节点已转过，但那个 part 已被删 | 链接失效，按新建处理 |
| 预览后导图或架构图又被改动 | 提交时带两个版本号，任何一个变了返回 409，页面提示并重新预览 |
| 同一位 leader 被选进两个 part | 预览报错，不允许提交 |

### 3.5 预览改前 / 改后

转换对话框两栏：**改前**是目标工作区当前的 part 树（含 leader）；**改后**是转换后的树，新建 part 带“新建”标记和可编辑名称，并入的带“并入”，已转的带“已转”，leader 变动带“移入 / 移出”。顶部是“挂到”选择和汇总（新建 X · 并入 Y · 放入 Z 位 leader），底部“确认转换”。预览是只读计算，不写任何数据。确认后在一个事务里写架构图（走 `domains.apply_ops`，架构图版本 +1，现有撤销栈因版本变化自动要求刷新）、写链接、导图版本 +1。

### 3.6 给助手开局作战的输入

导图结构（树、主题、想法引用、已转链接）由 `GET /api/personal/mindmap` 一次读到；转换的预览 / 执行接口就是助手日后“按导图起盘”的落地动作，阶段四直接复用，不另写一套。

## 4. 三视口布局

| 视口 | 布局 |
| --- | --- |
| 1280（桌面） | 左栏 54px + 主面板（导图形态收起右侧标签栏）。主面板内：标题栏、快速记、筛选栏，下面托盘 224px + 画布。操作条浮在画布底部中央，缩放组在右下，二者不重叠 |

| 375（手机） | 同 758；操作条折成两行网格（每格 ≥44px 高）；标题栏的“卡片墙 / 导图”在 ≤480px 只显示图标，避免挤压标题；快速记输入框吸顶；画布原生滚动平移；转换对话框改为全屏，“改前 / 改后”用分段开关切换，默认看改后，确认按钮吸底 |

浅色和深色都只用 `--studio-*` 与现有色板变量；分支色条取标签色板的前景色（`--tag-cN-fg`），在两种主题下都满足与卡片底色的对比。

## 5. 视觉方向取舍

做了两个方向的小样（只用于比较，不进仓库），在同一份示例数据上看浅色和深色：

- **A · 有机导图**：彩色贝塞尔枝干、下划线文字节点，最像传统思维导图。问题：节点只是一段文字加下划线，拖放落点和触屏点按区域都太小；选中态只能靠淡底色，扫一眼不明显；深色下彩色粗枝干抢过文字；和架构图的卡片语言完全两样，转换前后看不出对应关系。
- **B · Studio 卡片**（选定）：节点是与托盘、想法卡片、架构图 part 同一语言的小卡片（`--studio-card` 底、`--studio-border`、`--studio-shadow-sm`），左侧 3px 色条标识一级分支，连线是中性色圆角肘线。卡片有完整命中区域，拖放和触屏都可靠；选中用强调色描边加光晕，浅深色都醒目；节点转成 part 后形状一致，用户能直接看出“这张卡变成了那块 part”。代价是不如 A 灵动，用分支色条和主题节点的淡色底补回层次。

## 6. 第一版不做

- 多张导图、导图之间移动节点。
- 节点自由摆位（布局全自动，只保存结构、顺序和折叠）。
- 结构编辑的完整撤销 / 重做栈（只提供“移出节点”的撤销；移出本身不丢想法、不丢子节点）。
- 触屏长按拖拽（触屏走操作条与“上图”按钮）。
- 转换时新建 leader（阶段四助手开局作战负责）。

## 7. 待接线

本任务不改 `plugin/crew/web.py`、`plugin/crew/web_api/`、`chat*.py`。处理函数在 `plugin/crew/mindmap_api.py`，主控按下表接线：

### 7.1 HTTP 接口

| 方法 | 路径 | 处理函数 | 请求 / 返回 |
| --- | --- | --- | --- |
| GET | `/api/personal/mindmap` | `mindmap_api.snapshot(service.home)` | 返回 `{version, nodes, links}` |
| POST | `/api/personal/mindmap` | `mindmap_api.edit(service.home, data)` | 体 `{ops, base_version}`，返回 `{map, effects}` |
| POST | `/api/personal/mindmap/preview` | `mindmap_api.preview(service.home, data)` | 体 `{project, roots, parent_id, decisions, names, leaders}`，只读，返回预览 |
| POST | `/api/personal/mindmap/convert` | `mindmap_api.convert(service.home, data)` | 体同 preview 再加 `map_version`、`board_version`，返回 `{map, board_version, summary}` |

- 接法与 `/api/personal/notes` 一致：GET 加在 `Handler._dispatch` 的 GET 分支；三个 POST 路径加进 `web.POST_PATHS`，在 `Service._post` 里于 `personal` 相关分支旁按路径分派（不需要 `project` 查询参数，项目在请求体里）。`convert` 会写目标工作区的架构图，建议放进 `with self.write_lock:` 与 `/api/domains` 同样串行。
- 错误映射沿用 `_handle`：`board.Conflict` → 409（版本过期），`board.BoardError` / `ValueError` → 400。不新增异常类型。
- 局域网设备：`plugin/crew/remote_routes.py` 的 `GET_PATHS` 加 `/api/personal/mindmap`，`POST_PATHS` 加上面三个 POST 路径（与想法墙同属 `notes` 能力）。
