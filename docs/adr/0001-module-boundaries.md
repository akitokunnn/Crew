# 按能力模块化，传输、交互与原生执行分层

日期：2026-10-27。状态：接受；迁移验收见[任务清单](../architecture/WORKLIST.md)。

原因：用户要求后续重点修改 UI 和增加模组；集中式状态、业务分支、重复 CSS 与双份资源登记已经造成交互和交付缺口。

决定：

- 功能拥有自己的状态、约束、错误和清理；入口负责显式组合，依赖自上而下。
- UI 布局与业务状态分开；HTTP 功能自行登记；标准历史不理解原生协议；身份、任务准入与更新门禁分别管理。
- 保留可用模块和原有行为，不按行数拆文件，不通过传整个上层对象或空壳转发伪装解耦。
- 本轮不引入第三方动态插件宿主、通用事件总线或新调度策略；将来需要时另立决定。
- 模块接口、真实旅程、结构约束和包内验证互相补充，测试数量不代表产品正确率。

后果：新功能通过明确登记接入，修改可集中于所有者；接口变化需同步调用方、测试和简短文档。规范仅维护在[模块指南](../architecture/README.md)，不在多处重复。
