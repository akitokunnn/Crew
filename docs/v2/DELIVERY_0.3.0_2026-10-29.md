# Crew V2 0.3.0：交付与验收

源码位于 `rebuild/v2`，从 `a51a093` 的 V1 基线开始。本次提交不合入 `main`，不安装或重启正式实例。桌面和插件包版本均为 `0.3.0`；产品名称为 **Crew V2**。

## 可以体验的流程

- 顶部工作区标签保留各自的页面和草稿；普通文件夹可用，不自动初始化 Git。工作区默认打开任务、讨论、待拍板和人工 TODO 主页。
- 一个跨所有工作区的个人助手，与系统管理员分开。具体项目从新 leader 对话开始，名称可省略。全局助手可依据原始用户消息执行跨项目操作，操作保留来源和去重回执。
- 快速想法直接本地保存、编辑和收起，不调用模型；“开始聊”才创建 leader。创建响应丢失时先查回宿主登记的原对话；无法唯一确定时可人工核实并关联，不重放需求。
- leader 整理任务、验收和工作清单；工作项具有负责人、依赖、完成条件、进度与验收说明。成员不能继续派工。总会话、各任务和成员会话各自保留原生身份与消息路由。
- 人工 TODO 与 AI 工作清单分开；同一人工事项可关联多个任务，逐任务记录回执。完成待办不会解除用户手动暂停或停止。
- 每个任务单独选择“由我拍板”或“自主推进”。设置保存不启动模型，也不追溯处理旧拍板。
- 阶段报告可以在工作期间发布，不强制收尾；用户修改阶段说明形成新稿，旧报告保留。最终报告、用户验收和原任务反馈续轮保持独立记录。
- 成果版本保存明确文件清单及内容快照。恢复只影响所选文件，先核对后续修改，冲突时保留当前内容；中途失败保存逐文件进度，不重做已成功的文件。不执行任意 Git 回滚。
- 行为配置支持全局、工作区、会话覆盖，编辑、恢复继承、修改历史与实际发送清单。原生确认仅表示收到宿主内容，不宣称模型理解或加载了无法观察的私有提示。
- QQ、Lark 按行动意义提醒拍板、人工 TODO、阶段成果及最终结果；普通结束语不主动刷屏。明确平台拒绝最多自动重试两次，网络结果未知不盲目重发，各渠道独立持久回执。
- Codex 同一原生 thread 可显式交给桌面并接回；交出期间 Crew 禁止投递，返回时同步新增原生记录。中断的交接保留外部门禁和真实错误，须显式接回。

## 明确的边界

1. **真实 Codex 桌面往返尚未验收。** 已验证同 thread 协议、交接门禁、历史导入和失败恢复；假载体及深链不能证明实际桌面端成功接续，尤其不同 `CODEX_HOME` 的可见性。
2. 没有运行真实模型长任务，因此“模型主动发现任务、理解同意、持续完成”的实际体验仍需真实使用检验。宿主的状态、工具和隔离任务旅程已测试。
3. CC 原生客户端接续与 IDE 专项按本轮意见不作为初版重点。QQ/Lark 仅用假平台测试，未做正式渠道发送。
4. 安装器没有代码签名；本次构建和 PE 图标资源检查不等于在用户正式环境完成安装。正式 V1 未被更新或替换。
5. 工作区包保留该项目的清单、报告、人工 TODO、多任务关联、项目想法、提示历史和成果字节；全局助手、全局私人想法及全局设置不随单个项目迁移。原生控制和原操作授权只作历史，不恢复连接或自动执行。
