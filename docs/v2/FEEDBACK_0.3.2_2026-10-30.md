# Crew V2 0.3.2：体验反馈修复与证据

本轮基准为 `rebuild/v2` 的 `a31ca95`、桌面 0.3.1。改动提交到 `rebuild/v2`，不合入 V1 主干。正式 Crew、用户对话与认证未被重启或改写；真实 AI 仅按用户授权，在隔离 HOME 与临时项目使用原生发现的 `gpt-5.6-luna / low`。

## 逐项处理

| 用户反馈 | 本轮处理与实际边界 |
| --- | --- |
| 1. Codex 交出后接不回 | 定位到原生 `already has an active writer`；占用时明确提示并保留原生错误、同一 ID、历史和外部门禁。真实隔离客户端关闭原拥有者后可接回并回复；不假装抢占仍在线的桌面连接。真实桌面 UI 往返仍未验收。 |
| 2. 助手不回复 | 原生已有回复，助手状态却缺共享聊天组件需要的 `name`，渲染首段时报错。修复正式状态契约，浏览器显示回复、历史及草稿；真实 Luna HTTP 连续两条回复通过。Claude 首次启动误用 resume 的同类问题也修正，已有历史仍恢复同 ID。 |
| 3. 压缩卡住 | 修复真实原生事件中“用量先到、完成后到”导致完成事件遗漏；未知用量不伪造。压缩的 HTTP、进程、记录和 SSE 绑定具体任务，不串到总会话；忙时明确排队，总会话不被其他任务误禁用。 |
| 4. 删除对话右上任务按钮 | 删除总会话重复的任务资料快捷入口；任务内资料与交付入口保留。 |
| 5. 约束文本是否很多 | 实测旧 Sol 会话可见启动说明约 5.2 万字符、工具目录 JSON 约 5.8 万字符，格式不同，不能冒充精确上下文总量或 token。Crew 保存的行为配置为 4994 字符；去掉重复旧信任注入和重复读守则要求。详见提示审计。 |
| 6. 闪电、长正文、未知状态、断线 | 关系图改成有标题的“进行中的协作”，只展示最多两条有运行证据的简短摘要及余数；不把原生会话首条系统正文当成派工，不堆无运行证据的未知历史。删除此处闪电，连接线连续；完整历史保留在明确入口。 |
| 7. 是否另开任务窗口 | 本轮保持工作区内查看，固定返回任务清单。先保证同一工作区来回顺畅，不增加独立窗口与新的焦点切换。 |
| 8. browser access host 不可用 | 该错误出自原生浏览器工具，未发现 Crew 自己抛同一错误；底层宿主不可用原因仍未知。报告规则明确保留真实错误并标视觉未验证，仍提交可读正文及已有证据；不反复调用失效宿主、不把预览失败扩大为整个任务失败。 |
| 9. 进任务后不知如何返回 | 固定“返回任务清单”；任务状态只作状态显示，不承担导航。总会话、任务列表和各对话草稿保持独立。 |
| 10. 重复信任与自主推进限制 | 删除旧组信任 UI、资源及重复注入，新任务不继承隐藏的旧 leader 信任设置。任务决策与原生工具权限保持真实区别。AI 自行添加的约束标记真实 actor，不冒充用户硬性要求。 |
| 11. 评论无用 | 删除评论界面、菜单、缓存、处理分支及相关依赖；保留历史数据。 |
| 12. 验收证据与交付记录是否有用 | 实际证据对核对结果有用，改为报告内默认折叠的“验证详情”；保留通过、失败、未验证、样例、证据引用和未解决项，去掉与正文重复的交付叙述。 |
| 13. 小改不应开第二轮 | 已交付任务的普通追问使用讨论响应，保持业务状态、需求、报告和验收不变。确实修改时，AI 明确 amend 后在原任务、原内部轮次继续，保留旧交付与验收；只复核受影响工作。界面不再强调轮次或要求用户办理新轮手续。 |
| 14. 图二布局 | 去掉被外层裁成矩形的大阴影，保留清晰边框；同时展开关系图、待处理及窄窗口均在真实浏览器查看。 |

首轮全量共 2258 项，出现两项错误与一项失败：三处旧测试仍依赖每次 hook 注入历史信任说明。已改为检查无新消息时无重复注入、历史组信任不进入普通输入，保留组隔离、配置可读与不唤醒保障；完整 core 88 项、trust 25 项复验通过，旧 hook 反证两分支失败。首轮浏览器检查也曾抢在异步 history 到达前读取状态，受控 400ms 延迟可复现；检查现等待实际响应就绪，原“回复中”断言保留，旧 UI 反证仍失败。首次失败记录未覆盖，不能写成首次全部通过。

最终交叉审查还补齐已交付讨论的原生命令审批：读取命令可在用户明确批准后继续，仍执行既有 guard；未登记修改时的文件变更仍拒绝。此前仅 guard 放行、审批层却按目标已结束拒绝，现由实际审批回归与旧方法反证覆盖。此补修后重新全量回归和打包。

取消任务截图又暴露旧信任样式文件中夹带了多个入口共用的对话框外壳。已将仍有消费者的通用规则迁入主样式，旧信任资源保持删除；创建目标、创建组员、更换工具、取消任务均验证真实遮罩、居中与关闭返回。删除通用规则的反证确实出现表单落在页面底部，失败截图保留；该修复后再次重新打包。

真实小改的首次验收脚本在报告 pending 时过早关服，导致最终断言失败；重开同一隔离宿主后，正常后台同步在 2 秒内将已有报告收敛到 completed，原生进程 factory 禁止启动，0 次 AI 重做。原始失败与无 AI 收敛证据均保留，不把一次迟读伪装为模型重新交付。

规则防复发已在 `AGENTS.md` 的证据表绑定具体测试与浏览器检查。只读统计工具为 `scripts/audit-crew-prompts.py`。本轮原生方法按本机 CLI 0.165.0 实测；`thread/resume` 不支持替换 dynamicTools，已删除旧无效参数及其假验收，接回工具的可用性由真实调用验证。

前端完整命令为 `node --test plugin/tests/test_*.js`，桌面为 `npm --prefix desktop test`；浏览器为 `node plugin/tests/smoke_assistant_reply.cjs` 与 `node plugin/tests/smoke_v2_ui_revision.cjs`。Python 在 `plugin` 目录执行，测试进程设置 `PYTHONPATH=tests;.` 并清空继承的四个会话/执行身份变量；浏览器使用本机 Chrome 与 Codex 自带 Playwright。桌面隔离工作区检查另有 46 项通过。Windows 构建后实际执行便携版与目录版的 `desktop/scripts/smoke.cjs`、三个 EXE 的 `verify-icons.cjs`，并逐字节核对源码与包。最终源码快照覆盖 216 个生产文件，冻结后无变化；正式环境未部署，没有将本地检查称作 CI 通过。
