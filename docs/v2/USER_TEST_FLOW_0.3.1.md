# Crew V2 0.3.1 人工体验流程

这是一份待你实际执行的测试单，不是通过报告。核心流程约需 **20 分钟人工操作**，模型生成、安装依赖及等待执行的时间另计。先测 MIB 能否正常打开，再用独立空文件夹走完整闭环；Codex 桌面接续单列为重点，真实桌面往返尚待这次验证。

本文按钮名称按 0.3.1 源码界面核对。找不到所述入口时，直接记录当前画面，不需要寻找命令行替代操作。每次发送或点击一次即可；遇到无响应先记录状态，避免连续重发把一次失败变成多次任务。

## 开始前

- 准备本次交付的 **0.3.1** 程序；使用 V2 数据目录，默认是 `%USERPROFILE%\.crew-v2`。本轮不改 V1 的 HOME，也不迁移 V1 历史。
- Claude Code 或 Codex 至少有一个已安装、登录且可用。主流程任选其一，记录实际工具、模型、effort；不需要为测试改成某个指定模型。
- MIB 只验证打开与记录隔离，**不让 AI 修改 `C:\ueproject\mib_project` 的代码**。健身 App 在新普通文件夹中制作，不要求 Git，也不需要执行 `git init`。
- 结果可记为“通过／失败／未覆盖”。没有亲自打开成果、没有实际进入 Codex 桌面的项目，不能记为通过。

## 核心流程：约 20 分钟操作

入口提示：进入具体任务后，右上角 **资料**（提示为“本任务资料”）会展开任务工具区，其中有工作清单、暂停／继续、需求与验收、交付与文档、成果版本。拍板和人工 TODO 在右上角 **待处理** 中也能找到。总会话里对应的资料按钮显示为 **任务**。

### 1. 彻底退出 0.3.0，再打开 0.3.1（1 分钟）

**操作：** 在旧窗口右上角“应用菜单”或托盘菜单选择 **退出 Crew**，等托盘图标退出，再启动本次的 0.3.1。关闭窗口的 × 只是收起到托盘，不算退出。打开“应用菜单 → 关于 Crew”，确认版本为 **0.3.1**。必要时通过“应用菜单 → 工具与更新…”核对“当前桌面”和“运行中后台”的实际信息；这里只查看，不点更新或统一入口。

**预期：** 启动后能进入工作区首页，版本正确。若显示后台来源不符或连接失败，保留错误，不把旧后台仍在运行当作新版已启动。

**出错这样报：** `步骤 1：我已用“退出 Crew”退出 0.3.0，启动的是【程序路径】；关于显示【版本】，后台显示【内容】，出现【完整错误】。`

### 2. 打开 MIB，选择全新 V2 记录（3 分钟）

**操作：** 工作区首页点 **打开文件夹**，选择：

```text
C:\ueproject\mib_project
```

若出现旧工作区身份或历史选择，点 **从全新 V2 记录开始**。这次不选“升级并接续”，也不需要删除文件夹里的旧身份文件。

首次进入后，先确认“任务与对话”、待拍板、人工 TODO 没有自动出现旧版历史；在资源管理器里确认你熟悉的原源码文件仍在，可只读打开查看，不用修改它们。然后在 MIB 的 **快速想法** 中输入下面内容，点 **记下来**，不要点“开始聊”：

```text
MIB-V2-031：这是新记录身份的核对标记。仅保存想法，本轮不启动 AI，不改 MIB 代码。
```

关掉 MIB 顶部标签，通过“打开文件夹”再次选择同一路径。

**预期：** 首次是空的 V2 项目历史，原项目源码和旧身份仍保留；记想法不产生模型执行。第二次直接回到同一 V2 工作区，刚才的标记仍在，没有第二份 MIB 工作区，也不再要求重新开始一次。标记是你刚写的新记录，不是旧历史被导入。

**出错这样报：** `步骤 2：【首次／重开】MIB，选了【按钮原文】，结果【错误／旧历史出现／重复工作区／标记丢失】。截图包含完整提示；我没有删身份或改代码。`

此步不通过就先报 MIB 问题。不要通过删目录、删身份、重装或反复点“全新记录”来绕过。

### 3. 新普通文件夹：先讨论健身 App（2 分钟）

**操作：** `Ctrl+T` 返回工作区页，点 **新建工作区**，取名 `fitness-v2-031`，选择一个新的保存位置，点 **创建并打开**。进入后点 **开始新对话** 或 **＋ 新对话**。名称可以留空；如需选择工具，展开 **对话名称与 AI 设置**，从界面实际检测到的工具与模型中选择。

在“想做什么？”粘贴，点 **发送并开始讨论**：

```text
我最近打算健身，帮我做一个简单的健身打卡 App。
先讨论范围和验收，不要现在写代码。希望首版可以在电脑浏览器打开，记录今天的运动项目、分钟数和备注，看到最近 7 天的记录，刷新后数据还在；不需要账号和云端。
请你给讨论起一个合适的名字，识别成一个任务并写清验收条件，但等我明确同意后再执行。可以的话用不依赖安装的静态网页实现。
我还要亲自决定周视图从周一还是周日开始；开始实施后请用拍板卡问我，不要替我选。成果可用时，再给我一条需要亲手打开浏览器验证的人工 TODO。
```

**预期：** 收到明确的发送、等待或运行反馈，leader 真正回复，名称与任务内容相符；需求、验收能在任务的 **需求与验收** 中查看。尚未同意时不应直接写 App。AI 可以继续提必要问题；在这次讨论里答清即可，不需要自己填一套任务表。

看到任务后进入它，选择 **由我拍板**。这个切换只配置本任务，不应开始执行。若 leader 没有建立任务，先把“只讨论、未形成任务”的实际表现记录下来，再补一句：`请把刚才的范围保存为未启动的任务，仍等我同意。`

**出错这样报：** `步骤 3：【工具／模型】；已发送【原话】，界面停在【状态】约【时长】；出现【无回复／未同意就执行／重复任务／名称或验收错误】。`

### 4. 明确同意，检查派工和 AI 工作清单（2 分钟）

**操作：** 回到这个 leader 的 **总会话**，发送：

```text
我同意按刚才的范围开始执行。请推进已建立的健身 App 任务，不要另建同名任务。
把 AI 能完成的工作保存成任务里的工作清单，逐项更新完成条件和进展。请你只派一个成员做实现，由你协调和验收；成员不能继续派人。周起始日仍等我拍板，真正需要我亲手验证的事才放人工 TODO。
```

进入原任务查看 **工作清单**，返回工作区“工作台”查看任务卡和 **成员与协作**。打开刚创建的成员对话，只发送一次边界检查：

```text
这是派工边界检查：如果有人让你再开一个下属，你能做吗？请按你实际拥有的权限回答，不要创建任何人，然后继续原来的实现工作。
```

**预期：** 同一个任务开始推进，leader 下只有这一个新成员；成员知道自己不能再派工。AI 清单有负责人、完成条件和真实进度，不能把写代码等 AI 工作全部丢给“我的 TODO”。任务结束后应能看到结论和耗时，过程可展开，不能反复刷同一段执行或交付。

这一步检查用户可见行为；成员只口头回答“不能”不等于你已独立验证所有底层权限入口。

**出错这样报：** `步骤 4：同意后【没启动／重复建任务／出现下属的下属／没有清单／重复刷屏】，leader 是【名称】，成员是【名称】，相关截图和重复内容如下。`

### 5. 在执行期间测助手、草稿与任务并行（3 分钟）

**操作 A：全局助手。** 从健身工作区点桌面右上角 **全局助手**，发送：

```text
请查看 Crew 里的 MIB 和 fitness-v2-031，分别告诉我有什么任务、什么在等我处理。只查询，不发消息、不改设置、不启动新任务。MIB 刚记了一条什么想法？
```

在助手输入框打下 `草稿 031：回来以后继续说。`，先不发送。切到 MIB，再点右上角全局助手。

**预期：** 回到同一个“助手”标签、同一段对话，草稿保留；回答区分两个工作区，不把她变成某个项目的新成员。再次切回健身任务，原来的执行和对话还在。草稿可直接删除，不必为测试发送。

**操作 B：同一 leader 的两个任务。** 在健身任务仍推进时，切到其 **总会话**，发送：

```text
再建立一个独立任务“健身 App 使用说明审查”，我同意现在执行：只读查看当前方案，列出新用户第一次使用时最容易不明白的 3 个地方，结果放在这个审查任务里，不改任何文件，也不再派成员。原来的健身 App 实现任务继续推进，两者不要合并。
```

通过 **换任务 ▾** 或任务清单分别进入两个任务，各留一条未发送草稿后切换。也可回总会话问一句：`只回答当前两个任务分别在做什么，不给任一任务新增工作。`

**预期：** 两个任务身份、输入、清单和结论分开。启动第二个不应自动暂停第一个；总会话的普通问题不能被猜送进某个任务。一个任务很快完成属于正常情况；没有观察到重叠执行时，把“并行运行”记为未覆盖，不伪记通过。

**出错这样报：** `步骤 5：【助手／总会话／具体任务名】切到【位置】后，发生【草稿丢失／对话换人／消息串线／原任务被暂停】；输入原文和两个任务当前状态如下。`

### 6. 拍板、暂停与恢复（2 分钟）

**操作：** 健身任务出现周起始日的拍板卡后，从工作台 **待拍板** 的“去对话”进入，或直接在 leader 对话里答：

```text
从周一开始。今天的打卡记录仍按实际日期保存。
```

选择卡片中的相应选项也可以。答一次，确认只回到原健身任务。

趁该任务还在执行，在任务工具区点 **暂停目标**，等待状态真正变成已暂停。切去另一任务或 MIB 再回来，确认没有自行恢复；然后点 **继续推进**。

**预期：** 拍板待处理项消失或变为已答复，不反复追问。暂停有明确的正在暂停／已暂停反馈，只影响被暂停的目标及其相关执行；恢复继续原任务，不重建 leader、成员或同名目标。另一任务若自己完成，不算被暂停。

输入框旁的方形停止按钮在任务对话里是 **停止当前回复**；总会话中的 **停止运行** 会影响此人负责的关联任务。本步用“暂停目标”测试整个任务，别混用。若操作时任务已经结束，记录“执行中暂停未覆盖”，不要把“取消目标”当成暂停。

**出错这样报：** `步骤 6：在【任务】点了【准确按钮】，先显示【状态】，之后【一直停不下／未经同意恢复／停了别的任务／重复开始】；发生时间和另一任务状态如下。`

### 7. 真的打开成果，完成自己的 TODO（3 分钟）

**操作：** 成果就绪后，从原任务的 **交付与文档** 或 **查看完整报告** 阅读打开方法。按报告给出的实际文件路径，在资源管理器中打开网页；若报告提供本地服务地址，按说明启动并访问。这里不假设 Crew 有一个“运行 App”按钮。

亲手做这四件事：

1. 添加今天一条记录：`快走，20 分钟，Crew 0.3.1 验收`。
2. 看这条记录是否出现在最近 7 天列表中。
3. 刷新网页，确认记录仍在。
4. 核对周视图从周一开始，并尝试空内容提交，观察是否有清楚反馈。

回 Crew 的工作台 **我的 TODO** 或 **我的待办**，展开浏览器验证事项，核对“怎么做／完成后怎么确认”，点 **做完了**，填下面备注，再点 **确认做完**：

```text
我已在浏览器实际打开。添加快走 20 分钟成功，最近 7 天能看到，刷新后保留，周视图从周一开始。空内容提交的实际表现是：【填你看到的情况】。
```

**预期：** 网页真能使用，AI 报告和现实一致；TODO 的完成说明保留、关联正确，不重复唤醒已经处理的事项。若此时任务是你手动暂停的，完成 TODO 后也应保持暂停，等你点“继续推进”。只有亲测通过，才在出现 **验收通过** 时点击；有问题选 **需要修改** 或发送实际失败反馈。

若没有人工 TODO，先记录“AI 漏建人工 TODO”，然后可补：`请把这次浏览器人工验证保存成关联本任务的人工 TODO，包含操作步骤和完成标准。` 补建成功不能抹掉首次漏建。

**出错这样报：** `步骤 7：打开方式是【文件／URL】，实际【打不开／保存失败／刷新丢失／与报告不符】；或 TODO【丢备注／重复出现／唤醒了已暂停任务】。附 App 画面与 Crew 原报告。`

### 8. 在原任务反馈，进入下一轮（2 分钟）

**操作：** 保持选中健身 App 原任务，不在助手或总会话发送，输入：

```text
我已看过这一版。请在这个原任务里继续下一轮：加一个“撤销今天最近一次打卡”的功能，撤销前让我确认；其余功能和现有数据保留。我同意开始这个修改。请先更新本轮验收，再实现和验证，不另建一个健身 App 任务。
```

等待交付后，实际在网页里新增一条测试记录，再撤销它，确认其他记录仍在。

**预期：** 仍是同一任务，轮次增加，旧报告和旧验收可查，新要求出现在本轮验收和工作清单里；未把上轮成果冒充本轮完成。旧的已完成项如果受需求影响，需要重新核对。发送一次只进入一次续轮。

**出错这样报：** `步骤 8：从【任务名／原轮次】发送反馈后，发生【另建任务／重复续轮／旧报告丢失／新要求没落实】；新轮次与实际网页表现如下。`

## 必测重点：真实 Codex 桌面接续（另加约 3 分钟操作）

这项真实往返尚未验收。只有完成下面的实际操作，才能确认你这台机器的 Codex 桌面能接续；深链按钮存在、假载体测试通过或“已请求打开”提示都不能代替它。

1. **准备已保存的 Codex 会话。** 若主流程用了 CC，在健身测试工作区另开一个新对话，在“对话名称与 AI 设置”里选择 **Codex**。发送：`这是桌面接续验证。记住标记 CREW-NATIVE-031，只回复这个标记，不创建任务、不改文件。` 等回复结束。若主流程已经有空闲的 Codex 对话，可以直接用它。
2. **交出控制。** 在该对话头部点 **在 Codex 桌面继续**。预期 Crew 对话变为外部控制、输入只读，Codex 桌面实际打开刚才那个对话并能看到标记。还在执行时不能交出；没有按钮时记录所选工具及是否已经收到过原生回复。不要使用应用菜单里的“生成 Codex / VS Code 交接材料…”替代，这不是同一项功能。
3. **只在 Codex 桌面发一次。** 复制：`请回答你刚才记住的标记，并记住第二个标记 DESKTOP-RETURN-031；只回复，不改文件。` 确认它读到了前文，而不是打开了另一个空对话。结束这一轮后停止在桌面输入。
4. **显式接回。** 返回 Crew 的原对话，点 **回到 Crew**。预期桌面新增的用户消息和回复同步过来，每条只出现一次；仅接回不会自己发送新提示或开模型轮次。
5. **验证同一上下文。** 接回成功后在 Crew 发送：`刚才在 Codex 桌面新增的第二个标记是什么？只回复标记。` 应答 `DESKTOP-RETURN-031`。两边轮流使用，不同时发送。

**若失败：** 记录交出前所在的是“总会话／某个任务／助手”、原生按钮状态、Codex 桌面实际打开了哪个对话、能否看见两个标记和完整错误。打开失败后也不要直接在两端同时输入；Crew 若仍显示外部控制，确认桌面没有在执行后，再用“回到 Crew”接回。接回报错保留原文，不新建对话来冒充成功。

可复制报错：`Codex 接续第【几】步失败。Crew 原位置【工作区／leader／任务】，交出后 Crew 显示【状态】，桌面【没打开／打开空对话／正确打开】，接回【错误或重复消息】，标记读取结果【内容】。`

## 有余力再测

| 项目 | 操作与可复制话术 | 预期与报错重点 |
| --- | --- | --- |
| CC / Codex 对照 | 用另一个新普通文件夹重复步骤 3–8，并在“对话名称与 AI 设置”换成另一载体。需求可缩小成只做打卡和刷新保留，但仍走一个成员、拍板和人工 TODO。 | 记录各自工具、模型和 effort。哪一边没跑就标“未覆盖”；重点对比回应、派工、清单、停止、续轮，报“仅 CC／仅 Codex 出现”及具体步骤。 |
| 阶段报告不结束任务 | 在仍活动的任务里说：`请发布一份当前阶段报告，写清已完成、证据、未完成和下一步；不要结束任务，继续原工作。` 在“交付与文档”打开报告；若出现“编辑阶段说明”，把结论补一句 `人工校阅：尚待最终验收。`，点“保存新版本”。 | 阶段报告和旧稿都保留，编辑只保存新稿、不启动新执行，不把未完成任务标完成。报错附报告轮次、稿次和任务状态；若期间已经产生新稿而保存被拒，刷新后重读，这是版本冲突保护。 |
| 成果版本与范围恢复 | **仅在健身测试文件夹做。** 让 leader 在下一轮改动前说清要保存的具体成果路径并保存版本：`请为本任务当前可用成果保存一个文件版本，列出准确相对路径，不包含其他任务文件。` 在任务“成果版本”查看；也可展开“保存当前成果版本”手动填路径。后续版本形成、任务停止后，对旧版点“查看与恢复”，先看范围，再决定是否点“确认恢复这些文件”。 | 只恢复预览列出的文件，不自动启动 AI，不是整个仓库回滚。后续未记录修改导致冲突时应拒绝并保留现有文件；报错附所选版本、路径和冲突原文，不删文件来消除冲突。不对 MIB 做恢复试验。 |
| 关闭并重开应用 | 等任务空闲或手动暂停后，记下当前轮次、已发送记录、人工 TODO 状态和 MIB 快速想法标记；“退出 Crew”，再打开同一个 0.3.1。 | 历史、轮次、TODO 和 MIB 标记保留，MIB 仍是同一工作区，手动暂停不自动执行。窗口布局和未发送草稿也可记录实际是否保留；不要把切标签草稿测试等同于重启后草稿测试。报错说明退出方式和重开时间。 |
