# Crew 一键自更新设计（草案，待用户确认）

写于 2026-11-21。依据：用户裁决「Crew 一键更新，Mac 和 Windows 都做；发布流程加上 Mac 包」（见 [decisions-mac-remote.md](decisions-mac-remote.md)）。本文确认前不写代码。

## 现状

- 「工具与更新」已能查询 GitHub 上 `akitokunnn/Crew` 的最新正式发布（`desktop/src/crew-latest.cjs`），只读，不下载。
- 「统一后台」（`crew-updates.cjs`）已有一套成熟的切换流程：关闭新任务入口、确认整个 HOME 空闲、SQLite 备份并检查完整性、优雅停止自有后台、在原端口启动新后台。
- 最新发布 v0.3.17 只有 Windows 包：`setup.exe`、`win-x64.zip`、`portable.exe` 和 `SHA256SUMS.txt`。Mac 包只在 CI 构建产物里，保留 7 天。
- Mac：`/Applications/Crew.app` 属于当前用户，`/Applications` 对 admin 组可写，替换无需密码。Windows：NSIS 安装器按用户安装、不提权，可静默安装回原目录。

## 用户看到的流程

1. 启动时和每 6 小时检查一次（沿用现有）。有新版本时，「工具与更新」的 Crew 卡片显示新版本号和发布说明。
2. 点「下载更新」：后台下载本平台的包并校验，卡片显示进度。也可以开启「有新版本时自动下载」（默认关闭）。
3. 下载校验完成后，按钮变成「重启并更新」。点了以后先检查运行中的工作（见下文），通过后退出 Crew、替换、自动重新打开。
4. 重新打开后，卡片显示「已更新到 x.y.z」。失败时显示真实原因，原版本保留可用。

## 发布与下载来源

- 只认 `akitokunnn/Crew` 的最新**正式** Release（不含预发布和草稿），请求地址写死，不接受页面传入的地址。
- 发布流程加 Mac：给 Release 打 tag 后，`mac-build.yml` 在 macOS 构建机打 arm64 的 dmg 和 zip，上传到同一个 Release，并重新生成覆盖全部包的 `SHA256SUMS.txt`。`docs/DESKTOP_UPDATES.md` 的维护者流程同步修改。
- 只用 HTTPS 下载，只允许跳转到 GitHub 的下载域名；限制最大体积；保存到 `HOME/desktop/updates/<版本>/`。
- 校验：包的 SHA-256 必须与同一 Release 里 `SHA256SUMS.txt` 的记录一致；文件名、版本号与 Release 标签一致。没有 Apple 签名时，可信度来自「HTTPS + GitHub 账号 + 校验和」，这一点在设置里如实说明。

## 各安装形态怎么替换

| 形态 | 做法 |
| --- | --- |
| Mac（`Crew.app`，任意位置） | 下载 zip，用 `ditto -x -k` 解到临时目录；检查新包的 `codesign --verify --deep --strict`、包标识 `local.crew.desktop` 和版本号。退出 Crew 后，一个独立的小助手脚本把旧包改名为 `Crew.app.previous`，把新包移到原位置，再用 `open` 打开。所在目录不可写时，改为打开下载好的 dmg 并提示手动拖入。 |
| Windows 安装版 | 退出后静默运行 `setup.exe /S`，装回原目录（按用户安装，不提权），完成后自动打开。 |
| Windows ZIP / 便携版 | 无法安全地原地替换正在运行的程序，只下载并校验好新包，打开所在文件夹并说明替换步骤。（待确认，见下文 B） |

后台源码随新包一起更新，启动时按版本解出新的后台目录，沿用现有机制。数据目录、启动设置、局域网设备授权都不变。后台来源设为「自定义」的用户不受影响，卡片上会说明「自定义后台不随 Crew 更新」。

## 运行中的工作

- 点「重启并更新」时，沿用「统一后台」的检查：有会话正在回复、目标执行进行中、运维修复在跑，就不重启，并列出是哪些。用户可以等它们结束，也可以取消。
- 全部空闲时：关闭新任务入口，备份数据库，优雅退出，替换，重开。托管会话离线后，下次发消息会用原会话 ID 接回（现有机制）。

## 失败与回退

- 下载或校验失败：不动现有安装，显示原因，可以重试。
- Mac：新包首次启动并成功连上后台后，才删除 `Crew.app.previous`。如果新包启动失败（助手脚本在限定时间内没收到新包报告「已就绪」），就把旧包换回去重新打开，并留下日志。
- Windows 安装版：安装器失败时旧安装仍在，保留下载的安装包和安装日志。
- 每一步都写入 `HOME/desktop/logs/crew-self-update.jsonl`。

## 连接局域网主机时

客户端只更新自己。主机和客户端版本不一致时，沿用现有的「版本不一致」提示，不远程更新主机。

## 测试

- 单元测试：Release 解析、平台选包、SHA-256 校验、跳转限制、状态机、运行中工作的阻止。
- 隔离实测：搭一个本地假的 Release（不碰 GitHub），在临时目录里放一个旧版 `Crew.app`，走完「下载 → 校验 → 退出 → 替换 → 重开 → 删除旧包」，再故意让新包启动失败，验证回退。
- Windows 的静默安装由 Windows 端会话实测。

## 待确认

- **A. 安装要不要点一下**：推荐「自动检查 + 可选自动下载，安装必须点一次『重启并更新』」。另一种是空闲时全自动安装重启。
- **B. Windows ZIP / 便携版**：推荐只下载校验好、打开文件夹提示手动替换。另一种是解压到新的版本目录，并把快捷方式指过去。
- **C. 有会话在跑**：推荐不允许更新，等全部空闲；不提供「强制更新」。
- **D. Mac 旧版本**：推荐保留到新版成功启动后再删除。另一种是一直保留上一版，方便手动回退。
