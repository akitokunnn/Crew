| Codex · 常规施工与读取 | `gpt-6.2-sol`，medium / high | 盘点、按规格批量改同类入口、样式、补指定测试、性能测量脚本 |
| CLI Claude Code · 创意 | 本机默认模型，effort high | 需要创意和艺术感的产出：视觉方向、界面风格、新页面与作战室 / 思维导图 / 语音胶囊的视觉设计、图形与动效、文案调性 |

派活按三类分（用户 2026-11-27 裁决）：
- **死板的**（规格写得死、照做即可）→ Codex，按 `codex-dispatch` 流程。
- **需要判断的**（设计取舍、根因排查、产品判断）→ 主会话或主题会话自己做。
- **需要创意和艺术感的** → 用 `claude-dispatch` 流程（`~/.codex/skills/claude-dispatch/scripts/run_claude.ps1`，施工用 `-Mode full` 且限定在独立 worktree）调 CLI 版 Claude Code；**不交给 Agent 子代理，也不由会话或 leader 自己做**。

所有任务书写明范围、不在范围、编码要求（不写防御性代码）、测试差集为空；主控复跑验收并亲自截图复查，不以执行方的自述为准。

## 4. 冲突控制

- 同一文件同一时间只归一个会话；阶段三开工前由主会话出「文件归属表」，跨会话改动先找主会话协调。
- 主会话按完成顺序逐个合入集成分支；后合入的会话先并入最新集成分支并复验。
- 共享契约（操作清单格式、投递状态枚举、事件格式）由主会话定稿后才开工，各会话不自行修改。

## 5. 验收口径

- 每次合入：相关测试通过且新增失败差集为空；看 diff 有无越界、防御性代码、残留旧路径；对照交互清单抽查受影响的交互。
- 可见改动：`prove-it` 三视口浅深色截图，挑剔复查美观与可见性。
- AI 行为改动（提示词、守则、工具、助手）：自动测试后用便宜真实模型实跑一次，写明模型、实际表现和不符合预期之处。
- 全量测试在阶段五开始前和最终交付前各跑一次。
