# leader 巡查：候选场景，尚未启用

这一轮只讨论，不写巡查代码。下表的“可自己做”是供你选择的授权建议，不代表已经开启。现有 QQ 通知只转发白板上的明确事项，不会让 leader 自动接管或继续派活。

建议先考虑三类：明确失败的 Codex、阻塞流程的待拍板、成员结束一轮后仍有已批准的下一步。第三类需要先有可靠的计划与批准记录；不能看到 idle 就猜它还有事没做。

| 什么时候触发 | leader 看什么 | 建议可自己做 | 必须问你 |
| --- | --- | --- | --- |
| 成员一轮结束，已有批准计划还没做完 | 本轮结论、剩余项、批准出处、依赖 | 让原成员继续已批准的下一项 | 扩范围、改方向、没有明确批准记录 |
| 显示干活中，但约定的检查点到了仍无新动静 | 最后活动、长工具调用、原定用时 | 问一次是否仍在执行，记录原因 | 判断杀进程、重启、换窗口；沉默不能当卡死 |
| Codex 明确退出失败 | 派发者、任务、退出码、日志、工作目录 | 找原成员分析原因，提出原任务内的修复 | 自动重跑有费用或副作用的任务、改权限 |
| Codex 有开始记录，过了约定时限仍未结束 | 同一 run_id 的开始/结束事实、约定时限 | 询问派发成员，保留“尚未结束”的表述 | 停止任务、无依据地判失败 |
| Codex 成功退出，但成员没有验收 | 原完成标准、结果、成员汇报 | 提醒派发成员验收并汇报 | 把 exit 0 直接当产品完成、自动发布 |
| 借用设备超过预计归还时间 | 谁借、用途、预计时间、是否仍在用 | 问一次现状，协调下一位 | 强制归还、抢设备、覆盖设备内容 |
| 设备或文件归属发生冲突 | 双方任务、当前持有人、覆盖风险、所属组 | 组内排先后；跨组联系对应 leader | 目标冲突、强行释放、改守卫规则 |
| 阻塞流程的待拍板出现 | 原问题、选项、推荐、提问人、卡住了什么 | 同组归并；已有明确授权的可逆选择可按授权处理 | 业务取舍、费用、外部发布、未授权方向 |
| 待拍板越积越多 | 未答数量、最早时间、阻塞与重复关系 | 合并重复问题、排急缓，一次呈现 | 自创选项、只因为有推荐就替你答 |
| 你已回答，但会话迟迟没接收 | 答案保存时间、delivered_at、会话运行位置与状态 | 未来若你授权，提醒空闲原会话接收一次 | 偷偷另起同 ID、把已交给会话写成已读 |
| 收到交接或阶段报告 | 来源、目标、原文、既定下一步 | 按原分工转交，汇总关键变化 | 把未经验证的报告当已验收事实、扩任务 |
| 成员退出，仍有待交接工作或借用物 | 是否正常转 VS Code、剩余事项、资源状态 | 留下上下文，提醒本组 leader 收尾 | 把正常接续当崩溃、自动恢复进程 |
| 守卫拒绝操作 | 拒绝原因、资源/文件、重复次数 | 停止同类重试，解释冲突 | 绕黑名单、换工具绕拦截、改权限 |
| 达到你约定的预算或额度阈值 | 最新快照、采集时间、实际范围 | 合并提醒；按已有预算规则停止新派活 | 自创阈值、用过期快照宣称额度用尽 |

## 现有证据及缺口

- 白板事件有持久递增编号、时间、项目和会话，可在事务提交后按增量路由。
- 会话 task 和最后一轮原话能解释近况，但没有结构化的“批准计划 / 余项 / 完成验收”。这一部分不能凭时间邻近推断。
- Codex 新派活已记录开始和结束；孤立日志的最后时间仍不等于退出时间。
- 待拍板有完整问题、选项、推荐和送达时间。Claude 原生提问/权限等待只有状态，不能通过 crew answer 代替原生审批。
- 设备的预计归还时间只是预计，不是自动失效期限。

## 若下一轮决定实施

优先用成员结束、派活完成、拍板变化等事件触发；只让 leader 读取发生变化的一小批事实。设备到期和约定检查点用到点检查。普通 Stop、idle 或 token 增长不单独唤醒 LLM，不定时重复问“做完了吗”。同一事件只提醒一次，leader 的巡查报告不再次触发自己。

还需要你确定两件事：选哪些场景；这些场景里 leader 能否自行继续原任务、答可逆选择、提醒接收答案，还是只汇总给你。你睡觉期间不追加提问，也没有开启任何巡查。
