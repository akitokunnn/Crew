# Crew 网页交互设计

## 使用目标

这是 Akito 自己用的本机工作区。主要动作是跟 leader 聊目标、看进展、处理待拍板；已有的 VS Code 会话是协作的基础。页面要让人知道现在选中谁、它在哪里运行、在做什么、是否需要自己介入。

采用安静的浅色界面和深绿色主操作。对话占主要空间，状态与上下文围绕对话展开。数量只来自真实数据，进展只展示会话任务、报告和原话，不制造完成百分比。

## 页面结构

| 入口 | 主要任务 | 内容范围 |
| --- | --- | --- |
| 工作区（默认） | 与 leader 对话、了解当前组、原位拍板 | 当前项目、选中会话及所属组 |
| 会话管理 | 发现现有会话、收编、组建协作组、新建组员、挪组、退组、归档 | 当前项目的全部来源会话和候选 |
| 协作白板 | 查看资源、文件归属、待拍板、交接、日报和事件 | 当前项目 |
| 用量 | 查看会话、天、模型、agent 与 Codex 用量，导出 | 全机；明确标注，不跟随项目筛选 |

项目选择在全局导航中。分组和会话选择属于工作区。新建操作带当前项目与分组上下文，不要求在不同页面重复选择。

工作区首次进入优先选择当前项目的 leader；用户明确选过会话时保留选择。没有 leader 时，展示组建协作组的入口和可收编的会话。空项目可以直接从网页启用本机目录。

## 会话目录和来源

网页、VS Code、终端、离线及已归档会话都能在会话管理里找到。发现但尚未登记的活会话单独展示，收编后进入正式目录，不因没有网页聊天日志而消失。

名字优先使用 Crew 名称；未命名会话使用 transcript 的标题，再使用运行地址和短 ID。工作目录、分支、角色、分组作为次要信息，长路径可完整查看。

| 当前来源 | 对话主操作 | 可见历史 |
| --- | --- | --- |
| Crew 网页 | 在网页继续聊；可转 VS Code | 网页日志 |
| VS Code，已有网页日志 | 在 VS Code 接着聊；网页输入禁用 | 网页已有历史 |
| VS Code 或终端，无网页日志 | 在 VS Code 接着聊 | 展示任务和协作记录，不虚构网页历史 |
| 网页会话已暂停 | 发送后用原 ID 恢复 | 网页日志 |
| 已归档 | 查看历史和记录 | 只读，不能从残留输入框继续发送 |
| 来源未知 | 明确显示未知，展示可用信息 | 只提供后台确认可执行的操作 |

运行位置、工作状态、网页连接分开表达。空闲表示当前没有处理，不代表任务完成；已暂停表示网页进程不在运行，不代表失败。进程状态查询失败时保留最后已知信息并提示，不能把全部会话错误标为离线。

## 主要流程

### 把已有会话组成协作组

1. 从工作区或会话管理进入“组建协作组”。
2. 选已有成员和发现的会话；候选可以在同一流程起名，不必先逐一收编。
3. 输入组名和目标。组名也是 leader 名，界面明确说明。
4. 提交后显示启动状态，成功进入 leader 对话，成员归属更新。
5. 失败保留已选成员、名字和目标，错误指向具体原因。成员失效或重名必须可见，不静默跳过。

已有组的单个成员可挪组或退组。网页以会话 ID 指定成员，即使历史记录和新会话同名，也不会调整错对象。leader 留在自己的同名组，不能作为普通成员被挪走。

### 新建网页组员

1. 在当前项目选择新建组员，填写名字、任务、可选分组。
2. 需要独立 worktree 时展开该选项，默认使用项目目录。
3. 启动后选中新会话，首轮过程可见，工具调用可展开。
4. 用户可直接继续聊，也可按需转到 VS Code。

### 日常与 leader 协作

中间是当前会话，右侧是当前组成员的任务、状态、最近进展和待拍板。直接与组员沟通时，同样明确显示当前收件人。切换会话不会丢草稿或把消息发给另一个会话。操作过程中切换项目时，后台结果仍属于原项目，完成后提示查看，不把当前页面跳回旧会话。

工具调用默认折叠，保留名称、运行或完成状态和结果。回复逐步出现；用户在底部时跟随，用户向上阅读时不抢滚动。发送失败保留原文，可明确重试；断流自动重连并按事件序号接续，不能重复显示消息。

会话忙碌时不能再次发送，草稿仍可编辑。Enter 发送，Shift+Enter 换行，中文输入法确认候选时不误发。刷新只读日志，不启动新进程。服务重启后发言恢复同一会话 ID。

### 原位处理待拍板

每条显示提问人、问题、是否阻塞、选项、推荐和时间。用户能选择选项，也能补充自己的回答。提交中的同一条禁用重复操作，失败保留答案。

| 数据状态 | 用户看到的含义 |
| --- | --- |
| `status=open` | 等待回答 |
| 提交中 | 正在保存 |
| `status=answered` 且 `delivered_at` 为空 | 已保存，等待会话下一轮接收 |
| `delivered_at` 有值 | 已交给会话，不代表已读 |

回答不会自动唤醒空闲会话。保存后卡片留在可追踪的已答区域；未送达的回答不受最近 20 条历史限制。切换项目后，旧表单不能答复另一个项目的问题。

### 转到 VS Code

1. 检查空闲、进程归属和所选会话；忙碌时说明原因。
2. 打开会话所在的项目或 worktree 目录。网页显示完整目录和会话名字，此时原会话继续运行。
3. 用户确认正确目录的窗口已就绪，再点继续。取消只关闭提示，不结束会话。
4. 再次检查状态，释放自己的网页输入并等待正常退出，然后打开原会话 ID。
5. 若 VS Code 首次要求允许扩展打开链接，提示用户在该窗口确认。扩展启动后网页显示“在 VS Code 中”，保留历史并禁用网页发言。

失败不显示“已接续”或“成功打开原历史”；给出实际错误，允许从当前状态重试。同一个 ID 已在其他进程运行时，网页拒绝再次启动。旧终端只在明确确认且核对 PID 创建时间后关闭；VS Code 进程永不关闭。

网页宿主使用自己的 `crew-web` 标记。`sdk-cli` 会被本机扩展过滤，不能靠打开正确目录解决；不改用户 transcript 或扩展来伪造历史。

### 收尾分组

- 解散分组、保留会话：组员回到未分组，进程继续运行。
- 归档组和会话：从活跃列表收起，历史保留，进程继续运行；普通后续打卡不会让会话重回活跃。

确认界面说明选择及后果，不用含混的“删除”。归档不等于结束进程，界面不声称已经停止后台工作。

## 协作白板和用量

资源借还与文件归属提供责任人、用途、时间和说明。强制归还填写原因并明确确认；不提供没有后端支持的普通借用按钮。交接、日报和事件使用可扫读的时间顺序与来源，长原文可展开。

用量保留时间段、自定日期、排序、会话与 Codex 明细、模型和 agent 分布、CSV 导出。清楚展示 token 单位和价格估算含义，全机范围始终可见。加载和失败只影响该页，不清空工作区草稿或改变项目选择。

## 交互状态和适配

- 首次加载用局部状态占位，不能先闪现“没有会话”。没有项目、没有 leader、没有待拍板、没有记录各有对应说明和可执行下一步。
- 查询或操作失败保留内容和输入。成功反馈贴近发生动作的位置，不能只靠页面顶部瞬时提示。
- 3 秒状态刷新不能重建用户正在编辑的表单、夺取焦点、清除选择或改变展开中的工具详情。
- 弹层有标题、可访问的标签、关闭入口和 Esc 行为；关闭后焦点回到触发按钮。状态同时用文字表达。
- 大屏显示会话导航、对话和上下文；中屏上下文可收起；手机将目录和组内上下文变为清楚的抽屉入口。输入区和主操作可达，长表格在自身区域滚动，页面不横向溢出。
- 保留足够文字对比，次要文字仍可读。主要操作和危险后果各有明确文字，不依赖颜色或图标猜测。

## 接口与验收

沿用 `/api/state`、`/api/leader`、`/api/spawn`、聊天 history/send/events、收编与挪组、拍板和用量接口。补充：

| 接口 | 用途 |
| --- | --- |
| `POST /api/project/init {name,root}` | 无已选项目时也能启用已有目录，返回项目对象 |
| `POST /api/roster/move {session_id,to}` | 精确调整普通成员归属 |
| `POST /api/roster/remove {session_id,group}` | 精确指定普通成员退组；旧名字参数保留给 CLI |
| `POST /api/group/close {group,with_members}` | 明确解散或归档，不停止进程 |

验收使用临时白板和自建会话：首次启用项目、批量选已有会话与候选组建、leader 首页、成员切换、草稿和滚动、原位回答及送达、退组和归档、全部来源定位、断流和失败、用量筛选导出，以及 390 / 768 / 1280 / 1440 宽度对应的布局规则、触控和键盘操作。VS Code 接续需验证同一 ID、原历史与新一轮回忆；正式看板只读检查，不向用户原会话发送测试消息。

本轮按用户要求不再使用 computer use，不接管鼠标键盘。网页交互通过隔离 DOM 加真实 HTTP/SSE 验证；响应式和可读性按源码、字号、对比度及焦点逻辑核查。最终浏览器中的视觉感受由用户验收反馈。
