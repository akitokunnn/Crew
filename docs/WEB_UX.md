# Crew 网页交互设计

用户口径（2026-10-24）：网页仍以 leader 对话为主；新增人工待办优先落地页、项目目标下的信任模式、每组一列横排总览和评论。Claude 下属可接续到 VS Code，Codex 下属提供只读记录及 leader 协调，不会打开 Claude 的编辑器 URI。

当前新增交互详见 [WORKFLOWS.md](WORKFLOWS.md)。有未完成待办时首次无 hash 打开进入“我的待办”，明确对话 hash 保持原目标。拍板展示短问题、为什么要用户决定、推荐理由、完整选项及后果；背景折叠。没有摘要的旧卡显示补写入口，不以截断技术进展冒充已解释清楚。

## 用户怎么用 Crew

1. **在 VS Code 里探索**：用户开一个会话聊需求，聊清楚了，这个会话就专门负责这一块范围（比如"雷达"），范围里再拆的活由它自己派给 Codex。
2. **收编**：用户在那个会话里说"收编到感知"，会话自己 `crew join` 写好任务卡（负责范围、现在在做什么、怎么算做完）并通知 leader；或者用户在网页"待收编"里点它、起名、选 leader。收编之后用户照常在 VS Code 里和它聊，变化只是它知道自己归谁管。
3. **下属干活**：进展、卡住、要用户拍板的事，下属用会话间消息报给 leader。这一轮是用户本人在 VS Code 叫起来的，下属直接问用户；被 leader 或后台任务叫起来的，拍板交给 leader。
4. **leader 当中转站**：能定的自己定；要别的下属知道的只转给相关的人；剩下的攒成待拍板。用户在网页或 QQ 答完，Crew 先告诉 leader，leader 对在线下属用 SendMessage；离线则 `crew wake` 在后台续跑原会话，不另开替代下属。
5. **用户打开网页和 leader 聊**：看离开后发生了什么、答拍板、让 leader 开新下属、问进展。网页上不和下属聊天。
6. **收尾**：用户在 VS Code 里归档会话，Crew 跟着归档；leader 发现某个下属说做完了或者很久没动静，会问用户要不要归档。

leader 等同 Paperclip 里的 CEO：不写业务代码，只协调、派活、汇总、开新下属（不用批准），不发定时日报；自己手上的大块整理、盘点、核对、汇总派 Codex 去做（默认只读，10-23 用户定）。

## 一个项目一个标签页

项目比 leader 高一层，对应一个 VS Code 工作区窗口。右键“在这里启动 Crew”、`crew start` 或 `crew web --open` 打开 `/?project=名字`，页面里没有切换项目的入口；会话按所在目录（项目根和它下面的 worktree）归属，数据严格隔离。浏览器标签写成"(未挂起的待拍板数) 项目 · Crew"，图标是本项目主题色的 Crew logo。裸地址列出各项目入口，各自显示保存的主题色。

## 优先与置顶

leader 的右键菜单和对话头部“⋯”菜单均有“设为优先 ▸”，可选第 1 / 2 / 3 优先或取消，当前级别打勾；Git 管理员也可标记。选择级别是插入，后面的依次后移，最多保留三个；被挤出的 leader 自动取消，toast 显示“<名字> 已移出优先”，可撤销到修改前顺序。优先标记只给用户看，leader 不会获知。

置顶区在“全部 / 交流区 / Git”导航下面、Leader 列表上面；优先 leader 不在普通列表重复，没有优先项时隐藏。置顶项稍高，显示名字、目标、未读和待拍板。菜单“上移 / 下移”按所在分区调整优先级或普通顺序。区内拖动调整级别，普通列表拖入按落点插入（满三位同样挤出末位），拖回普通列表取消；拖动时显示空置顶投放区，轮询不重绘打断拖放。

左栏和“全部”页 leader 卡片共用 A 光边：第 1 级 5.5 秒快流光、2px 边与外发光；第 2 级 12 秒慢流光、1.5px 边、无发光；第 3 级 4 秒描边明暗呼吸、1px 边、无发光。数字角标 1 / 2 / 3 大小递减；对话头部、Ctrl K 搜索结果和拍板卡片也显示同色角标。“全部 → 等你拍板”中优先 leader 组按级别排在前面。颜色来自项目主题的浅 / 深色 token；雾蓝第 1 级用 #008F88，藕荷第 2 级和靛蓝第 3 级用 #687700。系统减少动画时全部动画停止，静态描边、发光、颜色与角标差别保留。

优先顺序按项目保存；归档、移出或结束后不显示，后面的级别补位，归档撤销后原顺序恢复。

## 页面结构

三栏，只为桌面设计（窄于 1180 时右栏收窄，再窄变抽屉）。

**左栏**

- leader（含 Git 管理员）可拖动排序，插入线提示位置；顺序按项目存数据库，换浏览器保留，保存失败提示并恢复服务端顺序，状态刷新不打断拖动。
- logo、项目名；Ctrl+K 找 leader、下属或操作。
- **全部**：整个项目的视图（见下）。
- **交流区**：紧接"全部"下面，是本项目所有 leader 和用户的公共频道；角标显示用户没看过的发言数。
- **Git**：紧邻“全部”常驻显示；无论是否启用，都能进入当前项目的 Git 页面。
- **leader 列表**：一个项目通常 2～3 个。每行是头像字、名字、一句目标；Git 管理启用后自动出现「git管理员」，名字旁带“Git”小标，点击沿用 leader 对话；琥珀色角标是未挂起的待拍板数，项目主题色角标是未读回复数；leader 正在回复时名字旁有跳动的三个点。
- **起 leader**：起名 + 一句"它要管什么" + “用什么模型”按钮行，模型下面是 effort 行。两行都把“默认”放在最前并默认选中，其余选项分别从 state.models / state.efforts 生成；effort 有 low / medium / high / xhigh / max。选 Haiku 4.5 时清空 effort、禁用整行并显示“Haiku 不支持”。默认跟账号设置走；组随之建好，成员以后再收编。
- **待收编**（显示正在运行的待收编会话数）、**用量**。
- 底部常驻 Claude 每周 / 5 小时、Codex 每周额度条（拿不到写"未采集"，不写 0），"我已离开"开关，深浅色切换（跟随系统 / 浅 / 深）。
- Claude 每周下面以次要文字小字显示“其中 Crew ≈ 12%”，不另画进度条。仅后端提供 crew 且 points 非 null 时显示；百分比取整数，低于 1 写“<1%”。悬停说明固定每 1% ≈ $20、社区区间 $16～27 及对应百分比范围、Crew 是进组 leader 和组员（含子 agent），以及本周 Crew 折合金额。

**中间：和 leader 的对话**
- 头部：名字、目标、"N 个下属 · M 个在干活"、可点击的“模型 · effort”标签，如“Opus 5.5 · xhigh”。优先取 applied 的实际值，尚未回报时取存储设置；空值写“默认”。点标签展开两组菜单：模型（默认 + 四个模型）、effort（五档，不含默认）；当前模型是 Haiku 时禁用 effort 整组并显示“Haiku 不支持”。切换后 toast 提示“下一步起用 …”。
- 上下文圈放在头部模型标签左边，也出现在左栏 leader 名字旁、下属卡片、“全部 → 在干活”列表和架构图组员节点。SVG 小圆环按 used / max 画弧，低于 50% 不渲染，达到 50% 橙色，达到 80% 红色；阈值只在 chat.js 的共用 `CrewContext` 组件定义 `CONTEXT_WARN=0.5` / `CONTEXT_DANGER=0.8`。title / aria-label 如“上下文 已用 52.1 万 / 100 万（52%）”；已用量与压缩前后数字不足 1 万显示整数，否则以万为单位保留一位小数；上限省去末尾 .0。
- 圈出现时，leader 头部和托管下属卡片旁显示“压缩”；忙时禁用，原因“正在干活，等这一轮结束再压缩”。VS Code 会话显示“去 VS Code 里输入 /compact”。leader 模型菜单另有“压缩上下文（当前 N%）”，任何占比都能用。提交前确认：“压缩「<名字>」的上下文？压缩后它只保留摘要，细节以白板为准。”
- **等你拍板**托盘置顶：本组未挂起的未答问题，默认收起成一行（问题、提问者、"推荐 A"），展开后点选项或直接写想法；答完卡片收起，toast 告诉用户哪个 leader 会去叫醒提问者，可以撤销。每道题可点"挂起"，移到托盘最下面默认折叠的"挂起 · N"区；展开后可直接答或"取消挂起"放回托盘。挂起仍是未答，不改变下属侧 `crew` 的题目状态；答复或撤回会清除挂起标记。取消挂起不通知任何人。
- **挂起通知**：挂起时 Crew 给提问者的 leader 排一条来源为 web 的通知，附题号、提问者名字与 cc_name；没有 leader 时不排。leader 用 SendMessage 转告提问者：不卡流程的按推荐继续；卡流程的先做别的，先别再问这道题。挂起的拍板不催用户，汇报时单独列出。
- 聊天记录：首次打开在"以下是你离开后的消息"处停下；用户的话在右侧气泡（QQ 来的标"来自 QQ"，截图显示缩略图）；leader 的回复用 Markdown 排版，流式出现；leader 做的事（查白板、发消息、开下属）折叠成一行灰字，进行中带转圈和闪光，点开看细节。`crew answer <编号> "<答复>"` 的操作行显示“答复拍板：<答复>”，过长沿用单行省略；`crew withdraw <编号>` 显示“撤回一道拍板”。聊天回复和组员卡片上的进展、汇报都写事情，不显示拍板编号；编号保留在命令和会话间内部消息中。下属发给 leader 的消息、Crew 送给 leader 的通知折叠成一行（"雷达 → 感知：…"），点开看全文。
- 输入框：Enter 发送、Shift+Enter 换行，输入法选词不误发；可以直接粘贴截图；leader 正在回复时可以继续打字但不能发送；草稿按 leader 保留。
- 实时进度行在消息列表最后、输入框上方：转圈 + “等模型回应 / 思考中 / 在写回复 / 在跑：<工具摘要>” + 本轮计时（如 1分23秒）+ “↓ 3.4k tokens”。state 每 3 秒刷新进度，计时按 state.now 校正偏差后每秒更新，token 在两次轮询之间平滑变化；空闲时整行消失，左栏三个点保留。
- 压缩请求显示“压缩上下文”系统分隔行，压缩阶段显示“压缩中”和计时；完成事件显示“上下文已压缩：4.6 万 → 9925”，并 toast“压缩完成：4.6 万 → 9925”。`<command-name>` 原始命令回显不出现在聊天里；刷新或重连不重复提示历史压缩。
- 滚到底时自动记为已读；没在底部时出现"回到最新"。

**右栏：本组架构图**
- leader 在上，下属竖排、圆角连线；每个下属显示名字、在哪运行（VS Code / 后台）、状态（在干活 / 等你 / 空闲 / 离线）、现在在做什么，下面挂着它派出去的 Codex：正在跑的带转圈和已用分钟数，24 小时内完成的带完成时间，更早的折叠成"更早 N 个"。
- 点下属弹出**下属卡片**（右侧抽屉）：负责范围、现在在做、最近进展、派出去的 Codex、借着的设备和占着的文件、看对话记录（只有网页托管过的会话有）。操作：**在 VS Code 打开**（后台运行的要两步：先开目录，窗口好了再接上同一个会话）、改名、换组、归档（可撤销）、停下这一轮（只对后台运行且正在干活的有效）；"更多"里是退组、移出 Crew。
- 后台下属卡片显示只读“模型 · effort”标签，同样优先取 applied；忙时显示阶段、计时与 token 简版进度。被叫醒后仍按普通后台下属交接到 VS Code；若 VS Code 留着旧标签，不直接在旧标签打字，使用卡片上的“在 VS Code 打开”。

**全部**
- 顶部四个统计都能点：架构图 / N 件等你拍板（只数未挂起）/ N 个在干活 / N 个待收编。
- 架构图：所有 leader 的树并排，点 leader 进对话，点下属弹卡片。
- 等你拍板：按 leader 分组列出未挂起的未答问题，卡片展开，可以直接答或挂起，每组有"进入对话"；挂起题在下方单独分组，可直接答或取消挂起。
- 在干活：正在干活的下属和它们正在跑的 Codex，后台下属显示阶段、计时和 token 简版进度，点开看卡片。

**待收编**
- 和 VS Code 会话列表一致：正在运行的直接列；没在运行、VS Code 也没归档的折叠成"展开 N 个"；退了组 / 独立的单独一组。
- 每行"收编"展开内联表单：名字 + 选 leader。收编后 leader 会收到通知去打招呼，下属下一次说话时知道自己的归属。
- 读不到 VS Code 会话列表时页顶写明原因。

**交流区**
- 头部“整理”按钮立即发起后台整理；正在整理时显示“整理中…”并禁用。失败 toast 显示真实错误原因，按钮恢复，可手动重试。服务每 10 秒检查各项目，卡后新增满 20 条也自动整理；自动失败后须再新增 20 条才尝试。
- 当前累积要点卡钉在消息列表上方，滚动消息时不移动。标题为“要点 · 截至 <时间> · 累计整理 <N> 条”；正文分“已定结论”“未定的事 · 在等谁”“各组跨组相关进展”，沿用交流区 Markdown 渲染。过长正文独立滚动，点击标题可折叠到标题行。
- 卡覆盖到的原文收成“已整理的 N 条原始发言 ▸”，默认折叠；展开后每页 20 条加载全文。卡后发言照常显示；没有卡时沿用原来的列表与分页。
- 中间显示本项目发言流：头像字、名字、时间、正文和点名标签。leader 的正文使用与对话回复相同的 Markdown 渲染和转义规则；点名显示为 `@名字` 小标签，用户自己的发言靠右，沿用聊天气泡样式。
- 首次打开拉取最近发言，往上点"加载更早的"分页加载历史，保留当前阅读位置。打开交流区或滚到底时推进用户已读位置，左栏未读角标归零；state 带未读数、最新发言 id、整理中状态、最近失败原因和当前卡 id，供页面刷新新发言及要点卡；未读计数口径不变。
- 底部输入框支持 Enter 发送、Shift+Enter 换行，输入法选词不误发。输入框上方一行"点名"，列出本项目 leader，点选切换，可多选；成功发出后清空正文和点名。
- 发出后 toast 提示"已发到交流区，点名的 <名字> 会被叫醒"；未点名时只提示"已发到交流区"。点名的 leader 通过既有通知在空闲时收到全文，没点名的在下一轮开始时看到摘要。

**用量**
- 三张额度卡：已用百分比、重置时间、采集时间。
- Claude 每周卡在重置时间上方显示“其中 Crew ≈ 12%（折合 $238）”，与左栏共用百分比格式和悬停说明；数字按当前 Crew 周窗口缓存显示，不随下方用量时间段切换。缺少 crew 或 points 为 null 时不显示。
- 今天 / 本周（周四起）/ 全部；"按结构"按 leader → 下属 → Codex 汇总 token 和折合金额，"按天"、"按模型"为次级标签；导出 CSV。
- 页脚注明：折合金额按 API 价换算只用于比较；额度是账户级；界面字体 HarmonyOS Sans。

**Git**
- 未启用时显示“启用 Git 管理”卡片：说明提交树、分支检查与 PR / CI 的用途，base / stable 两个下拉框只列本地分支。base 默认依次识别 develop、dev、main、master；stable 默认选与 base 不同的 master 或 main，没有则留空。点“启用”保存项目配置，自动开出独立 worktree 的「git管理员」后进入 Git 页面；默认 Sonnet 5.5 / high，可在管理员对话头部切换。
- 启用后页头显示仓库名和“和 git 管理员聊”，点按钮进入管理员的 leader 对话。base 卡片显示最新提交与 CI（✓ / ✗ / 进行中，链接到运行），并显示沿 base 第一父链找到的“最近一次合入”：匹配 PR 时显示编号和标题，否则显示来源分支或短 SHA，附合入时间。stable 卡片显示 base 领先它 N 个提交。右侧“刷新（fetch）”执行 `git fetch --prune origin`，旁边显示上次 fetch 时间；失败时显示报错原文。“更多 → 停用”需确认，确认后收掉管理员的组、删除配置，回到启用卡片。
- “合并请求”区块显示请求编号、状态、分支、提出者、说明、结果说明与 PR 链接。活动状态 open / merging / waiting_user 排在 merged / rejected 前；空队列显示提示，引导已收编会话提交自己的分支后用 `crew git request` 交给管理员。
Git 计算引用：base / stable 优先使用存在的 `origin/<分支>`，否则用本地分支，配置表仍保存分支名。领先 / 落后、已合入、merge-tree、默认最近范围 stable 分隔、最近一次合入与 base 领先 stable 的数量均使用此口径。卡片显示选定引用的最新提交；本地与 origin 不一致时显示落后、领先或分叉数量，没有对应 origin 时显示“没有 origin”。本地分支仍保留在分支表，base / stable 行显示各自与 origin 的关系。

- 两个标签为“树状图”和“分支”，默认树状图。页面打开时每 30 秒拉取一次数据。
- 树状图默认显示所有本地及 `origin/*` 分支可达、stable 不可达的提交，再加 stable 最新提交作为最近范围的最后一行，最多 80 条；stable 行显示“<stable> 在这里 · <日期>”横向分隔标。未设 stable 时默认最近 80 条。“加载更早的”先补完最近范围，再沿完整历史每次追加最多 80 条，提交不重复，泳道连线随追加重算。
- 左侧用手写 SVG 画泳道和连线，每个提交占一行，行高 `34px × --fs`。中间依次显示分支、PR、负责会话和单行省略的标题，右侧显示作者、相对时间、短 sha。base / stable 固定在最左两条泳道，base 使用主题色、stable 使用灰色，其它分支轮流使用调色板。本地分支 ref 实心、`origin/*` 淡色；PR 号带 CI 色点；负责会话用头像字显示。合并提交用加粗空心点，并显示“合并 #编号 来源分支 → 目标分支”或“合并 来源 → 目标”。
- 悬停提交点或整行打开详情浮层，点击固定；点别处或按 Esc 关闭。提交行可 Tab 聚焦，Enter 固定打开。浮层保持在视口内，显示可复制的完整 sha、标题、正文（默认最多 8 行，可展开）、作者、绝对与相对时间、父提交 / 合并方向、当前分支和 `origin/*` 标签，以及对应 PR 的标题、状态、CI 和链接。PR 只按 head 提交或 mergeCommit 精确对应。改动统计首次打开时按需请求，等待时显示“统计中…”，完成后显示“N 个文件，+A −D”和前 10 个文件；二进制文件单独标明。同项目同 sha 的统计在当前进程 / 页面内长期缓存。
- 点本地或 `origin/*` 分支标签高亮该分支独有提交，再点取消。“只看活跃分支”隐藏已合进 base 且 30 天没动的分支标签。
- 分支表将需要处理的分支排在前面。列为分支（标签与负责会话）、worktree、领先 / 落后 base、合并检查、PR 与 CI、最后提交（时间与标题）；冲突检查显示“冲突 N 个文件”，点击展开文件名。状态标签包括可合并、有冲突、落后要 rebase、等 CI、CI 红、已合并可清理、30 天没动、worktree 有没提交的改动。远端有、本地没有的分支单独一组。
- GitHub 不可用时，PR / CI 区域显示原因原文，其余 Git 数据照常显示。后台每 5 分钟检查 CI，base 最新提交失败、请求 PR 的 CI 从进行中变成成功或失败时叫醒管理员；用户在管理员对话里查看其处理与需要拍板的事项。

## 提醒

- 有新的未挂起待拍板或某个 leader 有新回复时，网页响一声短促柔和的提示音（浏览器要求页面先被点过一次才能出声）；挂起、取消挂起本身不响。
- 交流区新发言不响提示音，也不推 QQ；只有点名才给对应 leader 排通知，普通发言等它下一轮顺带看摘要。
- 左下角显示 QQ 状态：未配置、未绑定（去 QQ 给机器人发一句话）、连接中、已连上、重连中、被拒收（在手机 QQ 打开允许主动发送）、出错及真实原因；不加通道开关。
- 锁屏或打开"我已离开"时，提示"待拍板会推到 QQ"；每道未挂起的待拍板单独推到 QQ 私聊，点按钮或引用该条消息回复。QQ `/decisions` 只列未挂起的题，末尾说明挂起数。QQ 上用命令集直接和 leader 聊，收到后立即回执，结束后回传回复，见 [QQ.md](QQ.md)。

## 打开文件和网址

网页中 AI 写的 http / https 网址可以点击，在新标签页打开。leader 聊天、下属只读对话、交流区、拍板问题与选项、下属卡片进展等文字共用链接渲染。

Windows 绝对路径支持正斜杠和反斜杠；含 `/` 或 `\` 且以扩展名结尾的相对路径也可以点击，包括行内反引号中的路径。Markdown 链接可以指向本地文件。相对路径先按发言会话的 cwd 解析，找不到再按项目根目录解析；Markdown 预览中的相对图片和文件按该文档所在目录解析。

Markdown、文本、日志、JSON、CSV、代码和 PNG / JPG / JPEG / GIF / WebP / SVG / BMP 图片在右侧文件面板预览。Markdown 保留标题、列表等排版，文本以等宽字体显示，图片按比例缩放。文本最多读取 256 KiB，日志显示末尾，其它文本显示开头，截断时有提示。HTML / HTM、PDF、Office 文档直接调用电脑默认程序打开；HTML 由默认浏览器打开本地文件，保留相对资源。

打开方式由服务端白名单决定，前端使用解析接口的 `open_with` 字段：

- 文档类（md、txt、log、json、csv、xml、yaml、yml、toml、ini、cfg、html、htm、pdf、doc、docx、xls、xlsx、ppt、pptx、png、jpg、jpeg、gif、webp、svg、bmp）显示“用默认程序打开”。
- 代码 / 脚本类（py、js、cjs、mjs、ts、tsx、jsx、css、scss、ps1、bat、cmd、sh、c、h、cpp、hpp、cs、java、go、rs、rb、php、sql、vue、svelte、uproject、uplugin；Build.cs 属于 cs）显示“在 VS Code 打开”，通过 `vscode://file/` 打开文件。
- 其它所有类型，包括 exe、msi、com、scr、lnk、vbs、wsf、reg、jar、未知扩展名和无扩展名文件，只显示“这类文件不直接打开，请用‘在文件夹中显示’”及“在文件夹中显示”按钮，不执行打开操作。

扩展名匹配不区分大小写。面板提供“在文件夹中显示”，在资源管理器中选中文件。关闭按钮或 Escape 可关闭面板。文件不存在或路径是目录时显示原因，不打开空面板。

## 右键菜单

左栏 leader 可以右键，对话页头部的“⋯”打开同一菜单：打开对话、停下这一轮、压缩、模型和 effort、改名、上移/下移、看本组架构图、转到 VS Code 里聊。leader 在网页收到用户消息后续跑。改 leader 名同步修改组名。模型子菜单与原模型按钮共用内容；Haiku 的 effort 灰掉并说明原因。忙时不能压缩或接续到 VS Code，VS Code 会话的压缩项提示去那边输入 `/compact`；排序到边界时对应方向灰掉。

危险项“结束这个 leader ▸”展开下一级选择，不再弹确认框。有下属时可选“连下属一起归档”或“只结束 leader，下属退回待收编”，说明行列出下属总数与正在干活的人数；无下属时只显示“结束（组里没有下属）”。两种都会归档 leader、关闭分组，toast 的“撤销”恢复 leader、下属状态、归属和分组。Git 管理员此处显示灰色的“到 Git 页关闭 Git 管理”，可点击跳到 Git 页，没有通用结束操作。

下属在四处可右键：全部页架构图节点、右栏本组架构图节点、在干活列表行、卡片头部。不需要先打开卡片，就能在 VS Code 打开、看对话记录（有网页记录时）、停下这一轮、压缩、选择模型与 effort、改名、换组、退组、归档、移出 Crew；离线时可以叫醒。禁用项有原因提示，归档与移出提供 toast 撤销。操作始终使用菜单目标的会话 ID。

聚焦 leader 或下属后，菜单键或 Shift+F10 打开菜单。上下键选择可用项，右键进入子菜单，左键和 Esc 退回上一级；在主菜单按 Esc 关闭并还原焦点，点别处关闭。鼠标悬停或点击带箭头的项也能展开，子菜单贴近触发项并限制在窗口内。

转到 VS Code 先打开目录，窗口就绪后再接上同一个会话；leader 使用小对话框说明接续步骤。归档或移出会停止网页托管进程，忙闲都停；撤销不会自动启动；leader 下次收到网页消息后续跑，下属下次发消息或叫醒时续跑。只结束 leader 时，退组下属继续运行。
