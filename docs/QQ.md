# QQ 通知与远程回复

Crew 使用 QQ 官方机器人，把离开电脑时需要处理的事发到你的 QQ 私聊。只有一个 QQ 通道，不需要额外启动通知程序。所有项目的 leader 共用这个机器人，用命令切换当前对话。

`/projects`（`/p`）列项目，`/project 项目名` 选项目，`/leader 名称` 在该项目选人，`/where`（`/w`）确认目标；原有持久编号 `/1` 等仍兼容。引用 leader 原消息回复会回到原项目与 leader，不改变普通文字的当前选择。结构化拍板附理由与选项后果，修订后旧按钮拒绝提交。`/todo`（`/t`）查看人工待办，离开时新增人工事项会提醒一次，共享给多个任务的同一事项不会重复提醒。实现和 Lark 设计边界见 [REMOTE_CHANNELS.md](REMOTE_CHANNELS.md)。

## 建机器人与配置

1. 在 [QQ 开放平台](https://q.qq.com/)使用个人主体创建机器人，按平台的接入流程启用单聊和事件接收，取得机器人的 AppID 与 AppSecret；测试阶段把自己的 QQ 号加入平台要求的测试范围。
2. 打开 **设置 → 消息渠道 → QQ**，填写 App ID 和 App Secret，点击“保存并连接”。凭证写入所选 Crew HOME 的 `qq.json`，保存后立即生效，不用重启服务。已有 Secret 留空保留，设置页不会回显。
3. 等待状态变为“等待绑定”，复制页面的 `/bind 绑定码`，用自己的 QQ 账号私聊机器人。新连接必须提供绑定码，不再把任意首个私聊者自动绑定；已有主人保留。发 `/h` 查看命令。
4. 在手机 QQ 的机器人会话中打开“允许主动发送”。点击设置页的“发送测试通知”，在手机确认收件。被拒收时页面显示平台原因。
5. 凭证、权限或网络修正后使用“重新连接”；“断开连接”保留凭证，“重新绑定”生成新码并解除旧主人控制权。

也可以在所选 HOME 维护 `qq.json`（`app_id`、`app_secret`、`enabled`），但运行中的连接请通过设置页保存应用。完整双渠道说明见 [REMOTE_CHANNELS.md](REMOTE_CHANNELS.md)。
Crew 自己的状态写在 HOME 的 `notify.json`，包括 `owner_openid`（主人）、`since`（通知起点）、`manual_away`（手动离开）、`current_leader_session_id`（当前 leader）和 `leader_numbers`（稳定编号）。这些字段由 Crew 加锁直接写，不要把凭证放进去。

左下角会显示 QQ 未配置、未绑定、连接中、已连上、重连中、被拒收或出错及原因。未绑定时在设置页复制绑定命令并私聊机器人；出错时按真实原因检查凭证、网络或平台状态。传输层负责重连，不能继续重连的错误会停止收发，修正原因后点击“重新连接”。

## 离开时推送

网页打开“我已离开”，或本机桌面代理报告锁屏时，Crew 视为离开。锁屏查询沿用已有桌面代理，不启动或操作桌面工具；代理不可用时网页会显示原因，可以使用手动离开。睡眠、休眠、注销或关机期间不能接收消息。

手动点“我已离开”时立即推送当下的事项；锁屏离开，或离开期间新出现的事项，从第一件起等约 30 秒成批处理：每道未挂起的未答拍板单独发送一条 Markdown，标明 `项目·leader 待拍板`、问题、选项和建议，不显示拍板编号。推荐项排在按钮第一位，同一道题只能选一次，点击后显示“已选：…”。没有选项或超过 5 行 × 5 个按钮时，消息提示引用回复。真实错误、失败的 Codex 任务和明确登记的 leader 报告合成文字；人工 TODO、明确发布的任务阶段报告及最终报告分别保留独立回执。发送前已处理或挂起的事项不发送，已推过的事项不再推。

普通等待状态和 leader 每轮结束句不主动外推；QQ 私聊发起的问答仍回到 QQ。收到明确平台拒绝时最多自动重试两次，间隔 5、10 秒，重启不重置次数；接收状态未知的网络中断或崩溃不盲重发，原错误和尝试回执保留。设置保存只保存配置，测试消息必须由用户明确点击发送。

实际发送结果和题目、leader 的关系保存在本机数据库；入站消息和按钮按事件编号去重。发送失败保留明确原因，不自动重复发送。不要把失败提示当作送达确认。

## 私聊命令与聊天

不带 `/` 的普通文字发给当前 leader；以 `/` 开头的内容由 Crew 作为命令处理，不交给模型。

| 命令 | 作用 |
| --- | --- |
| `/help`、`/h` | 查看帮助 |
| `/leader`、`/l` | 列出所有项目的 leader：稳定编号、`项目·leader`、状态、未读、未挂起的待拍板数，标记当前 leader |
| `/leader 2`、`/l 2`、`/2`（其他编号同理） | 按 `/leader` 的编号切换当前 leader；归档后的编号不复用 |
| `/decisions`、`/d` | 把未挂起的未答拍板逐条重发，带按钮；最多发前 10 道，并说明剩余数；有挂起题时末尾说明“另有 N 道挂起” |
| `/back`、`/b` | 我回来了：关闭手动离开，并说明是否仍因锁屏被视为离开 |

命令不分大小写，忽略首尾空白。leader 列表沿用项目顺序，项目内按网页保存的顺序显示，编号固定、归档后不复用。

还没选 leader 时，先 `/leader`，再发 `/1` 这样的编号命令。普通文字入队后马上收到“已转给 项目·名字”；leader 正忙时收到“项目·名字 正忙，排在后面”。网页聊天记录标“来自 QQ”。“我已离开”只决定提醒是否主动推送，聊天回传始终工作。

网页后台停止的 leader 会按原会话 ID 恢复；在 VS Code 或其他进程运行的 leader 会明确提示无法接收，不会另起一份。leader 这一轮结束后，最后一段文字以 Markdown 发回，标题是 `### 名字 · 项目`，带分隔线；没有文字或启动、运行失败也会回复原因。长回复按段落分段，`TEXT_LIMIT = 2000`，便于手机阅读。

截图与文字一起发给当前 leader，沿用网页图片校验和保存：最多 5 张、单张不超过 5 MB。语音使用 QQ 自带的识别文字；没有识别文字时回“没听清，请打字”。视频、文件回“暂不支持”。

## 答拍板

直接点拍板消息下的按钮，或在 QQ 中引用那条拍板消息、输入自由文字。引用其他消息或不引用时，文字作为普通聊天交给当前 leader。

暂时不急着答的题可以在网页挂起，仍保留为未答；挂起区里可直接答或取消挂起。挂起后不再主动推到 QQ，`/decisions` 只说明挂起数量。

按钮先应答交互，再检查内部问题标识、选项序号和题目是否未答。按钮数据无效时回复“按钮无效，请先 /decisions。”题目已在别处答过时回复“这道题已处理”；提问者已归档或移出时不保存，并提示先恢复。答复保存后回执 `已保存：<问题前 20 字>…，已转告 leader。`，问题不超过 20 字时不加省略号；没有 leader 时去掉“，已转告 leader”。Crew 给 leader 排通知，由 leader 原样转给提问的下属、叫它继续。网页聊天回复、QQ 上 leader 的回复和组员进展都写事情，拍板编号仅用于命令和会话间的内部消息。

## 规则出处与验收

平台规则以 [QQ 官方消息总览](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)、[单聊消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)和[消息按钮](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/msg-btn.html)为依据。通知层按 `qq.py` 的事件和方法契约调用传输层，不管理额外的事件子进程。

隔离测试使用假 QQ 客户端和假模型进程，验证推送、绑定、命令、拍板、附件、回传和错误状态；真实 QQ 收件、按钮点击、手机主动发送权限由主控实测确认。

`/leader` 列表中，优先 leader 按有效级别排在最前，名字前加“★1”“★2”“★3”；原有编号保持不变。
