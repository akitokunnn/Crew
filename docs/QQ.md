# QQ 通知与远程回复

Crew 使用 QQ 官方机器人，把离开电脑时需要处理的事发到你的 QQ 私聊。只有一个 QQ 通道，不需要额外启动通知程序。所有项目的 leader 共用这个机器人，用命令切换当前对话。

## 建机器人与配置

1. 在 [QQ 开放平台](https://q.qq.com/)使用个人主体创建机器人，按平台的接入流程启用单聊和事件接收，取得机器人的 AppID 与 AppSecret；测试阶段把自己的 QQ 号加入平台要求的测试范围。
2. 在 Crew HOME 下新建 `qq.json`。默认 HOME 是 `%USERPROFILE%\.crew`；使用 `--home` 时，以指定目录为准。内容只有机器人凭证：

   ```json
   {
     "app_id": "你的AppID",
     "app_secret": "你的AppSecret"
   }
   ```

3. 启动或重启 Crew 网页服务（`crew web`）。不存在 `qq.json` 就是未配置，不启动 QQ 收发线程；凭证只在启动时读取，Crew 不会改写它。
4. 在 QQ 私聊给机器人发第一句话。第一个私聊者会成为主人，机器人回复绑定说明；之后只接受主人的消息和按钮，其他人只记日志。发 `/h` 查看命令。
5. 在手机 QQ 的机器人会话中打开“允许主动发送”。Crew 的提醒、回执和 leader 回复都使用主动发送；被拒收时网页会显示操作提示，下次发送成功后恢复。

Crew 自己的状态写在 HOME 的 `notify.json`，包括 `owner_openid`（主人）、`since`（通知起点）、`manual_away`（手动离开）、`current_leader_session_id`（当前 leader）和 `leader_numbers`（稳定编号）。这些字段由 Crew 加锁直接写，不要把凭证放进去。

左下角会显示 QQ 未配置、未绑定、连接中、已连上、重连中、被拒收或出错及原因。未绑定时去 QQ 给机器人发一句话；出错时按真实原因检查凭证、网络或平台状态。传输层负责重连，不能继续重连的错误会停止收发，修正原因后重启服务。

## 离开时推送

网页打开“我已离开”，或本机桌面代理报告锁屏时，Crew 视为离开。锁屏查询沿用已有桌面代理，不启动或操作桌面工具；代理不可用时网页会显示原因，可以使用手动离开。睡眠、休眠、注销或关机期间不能接收消息。

首条事项等待约 30 秒：每道未答拍板单独发送一条 Markdown，标明 `项目·leader #题号 待拍板`、问题、选项和建议。推荐项排在按钮第一位，同一道题只能选一次，点击后显示“已选：…”。没有选项或超过 5 行 × 5 个按钮时，消息提示引用回复。等待、错误、失败的 Codex 任务和 leader 阶段报告合成一条文字。发送前已处理的事项不发送，已推过的事项不再推。

实际发送结果和题目、leader 的关系保存在本机数据库；入站消息和按钮按事件编号去重。发送失败保留明确原因，不自动重复发送。不要把失败提示当作送达确认。

## 私聊命令与聊天

不带 `/` 的普通文字发给当前 leader；以 `/` 开头的内容由 Crew 作为命令处理，不交给模型。

| 命令 | 作用 |
| --- | --- |
| `/h` | 查看帮助 |
| `/ls` | 列出所有项目的 leader：稳定编号、`项目·leader`、状态、未读、待拍板，标记当前 leader |
| `/1`、`/2`… | 按 `/ls` 的编号切换当前 leader；归档后的编号不复用 |
| `/q` | 把未答拍板逐条重发，带按钮；最多发前 10 道，并说明剩余数 |
| `/back` | 我回来了：关闭手动离开，并说明是否仍因锁屏被视为离开 |

还没选 leader 时，先 `/ls`，再发 `/1` 这样的编号命令。普通文字入队后马上收到“已转给 项目·名字”；leader 正忙时收到“项目·名字 正忙，排在后面”。网页聊天记录标“来自 QQ”。“我已离开”只决定提醒是否主动推送，聊天回传始终工作。

网页后台停止的 leader 会按原会话 ID 恢复；在 VS Code 或其他进程运行的 leader 会明确提示无法接收，不会另起一份。leader 这一轮结束后，最后一段文字带 `项目·名字` 前缀发回；没有文字或启动、运行失败也会回复原因。长回复按段落分段，当前 `TEXT_LIMIT = 2000` 是占位上限，**待主控实测**。

截图与文字一起发给当前 leader，沿用网页图片校验和保存：最多 5 张、单张不超过 5 MB。语音使用 QQ 自带的识别文字；没有识别文字时回“没听清，请打字”。视频、文件回“暂不支持”。

## 答拍板

直接点拍板消息下的按钮，或在 QQ 中引用那条拍板消息、输入自由文字。引用其他消息或不引用时，文字作为普通聊天交给当前 leader。

按钮先应答交互，再检查题号、选项序号和题目是否未答。题目已在别处答过时回复“这道题已处理”；提问者已归档或移出时不保存，并提示先恢复。答复保存后回执 `#题号 已保存，已转告 leader`，Crew 给 leader 排通知，由 leader 原样转给提问的下属、叫它继续。

## 规则出处与验收

平台规则以 [QQ 官方消息总览](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)、[单聊消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)和[消息按钮](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/msg-btn.html)为依据。通知层按 `qq.py` 的事件和方法契约调用传输层，不管理额外的事件子进程。

隔离测试使用假 QQ 客户端和假模型进程，验证推送、绑定、命令、拍板、附件、回传和错误状态；真实 QQ 收件、按钮点击、手机主动发送权限和文字长度上限由主控实测确认。
