### 作战室（反馈第 8、9 条）— 2026-11-28

1. **入口**：放在最左边那一竖条里，不放右侧。主控补充：作战室按工作区算，入口就放在 leader 列表下面；有作战进行时，图标上显示状态（进行中 / 等你定）。

   - 目标完成前领头不能自己收工，有三种例外：
     - 用户手动叫领头停；
     - 领头判断目标很难完成，可以停，但要说明理由；
     - 预算花完。
   - 预算只在用户提出时才有。计划书里写了预算，领头开局时要说出来。
5. **作战计划书**：
   - 形式是 md 文档，走的流程和我们现在一样：用户和领头聊，用户给的需求可能很粗，由领头整理清楚写成计划书，用户敲定后才开打；

6. **细节归领头**（同日补充）：上面这些细节，以及作战室里类似的取舍，都由领头和不同的 AI 讨论后自己定下来去跑，不逐条回来问用户；用户只看最终的计划书。

## 评审采纳（astra 一轮，2026-11-28）

全部采纳，只有一处例外：旧 Codex 线程被续用期间仍可能出现在桌面版里，接受为已知限制，见 M19′。下面各条是对前文 M 条的修订，同号以这里为准。

### 作战室

- **M4′ 开局顺序**：普通开房和助手开局都改成同一个顺序：
  1. 在一个写事务里检查本工作区有没有房，没有就占下一个**筹备房**；
  2. 领头和用户谈，写计划书；
  3. 用户批准某个计划版本；
  4. 批准之后才建 leader、邀请成员、建任务、发公告。

  助手开局原来是先建 leader 再开房，改成以上顺序。每一步带稳定的请求 ID，失败后可以接着做，界面上能看到做到了哪一步。同一个房间、同一个版本的批准只会成功一次。
- **M5′ 计划书条目**：
  - **ID**：计划书的条目带稳定 ID，修订时按 ID 保留已勾的状态和证据。
  - **对应关系**：
    - 「分工」→ 负责人 + 事项，草稿阶段可以写“拟任”负责人；
    - 「等你定」→ 问题、推荐值、答复；
    - 「完成标准」→ 可核验的标准。
  - **解析失败**：缺小节、ID 重复、负责人对不上时，指出具体是哪一行，继续沿用上一个已批准的版本。
  - **建事项**：批准和生成事项在同一个事务里，重复批准不会重复建事项。
- **M2′**：「按推荐开打」提交的是用户实际看到的那个版本、每一项的推荐值，以及用户提出的预算。下面三种情况各给明确提示，不能静默：缺推荐值、完成标准解析失败、确认期间版本被改。
- **M6′ 存储和权限**：
  - **状态**：数据库保留 `open/closed`，兼容旧数据，另加阶段字段（筹备 / 作战）、草稿版本、已批准版本、关闭原因。
  - **领头资格**：新房的领头单独判定：本工作区的 leader 或工作区助手可以，系统管理员不行。旧房的继续操作仍按原来的权限。
  - **旧房迁移**：
    - 原来 `open` 的房映射成“作战中”，没有已批准计划的标成历史房，保留原来的收尾入口；
    - 系统管理员牵头的旧房也给用户一个收尾通道；
    - 迁移可以重复执行，不会补发邀请。
- **M7′ 出口一共六种**，在历史里分别显示：
  - **正常完成**：必须有已批准、非空的完成标准，并且全部勾上；
  - **用户叫停**：立即生效，不受领头离线或计划书坏掉的影响；
  - **领头放弃**：必须写理由，理由发到和用户的对话里；
  - **预算花完**：先暂停，由用户选择结束还是追加预算；
  - **筹备期撤销**；
  - **旧房退出**。

  房间结束时，撤销还没送出去的守护唤醒，只停本房的执行。
- **M8′ 守护按“事项 → 执行”绑定判断**：只对“可以干活、而且确认在闲着”的时段计时。下面几种情况不算闲着：等用户、等审批、预算暂停、人工停止、外部窗口状态未知。

  去重按“房间 + 事项 + 负责人 + 这次闲下来的开始时间”记进数据库。恢复干活之后再停下来，才会再提醒一次。重启后不重复提醒。成员在别的任务里忙，不算本房有进展。
- **M9′（替代 M9）作战交流不进私聊**：
  - **数据归属**：房内消息、工具回执、模型回复、未读、摘要都带房间归属，投递批次不和普通私聊混在一起，也不再把房内的点名投影成私聊气泡。
  - **在哪里干活**：成员优先在本房事项绑定的任务执行里干活；没有执行时，开一个本房专用的上下文。注入的内容是：计划书版本、本人负责的事项、房内增量。
  - **私聊**：只保留原来的历史。
  - **状态显示**：卡片上的状态按实际执行推出来，不用一个“当前房号”字段覆盖事实。
- **M10′ 上下文**：计划书修订和事项变更要单独送达，即使房里没有新帖也要送。送达对象是实际的任务执行，助手当领头、不在成员表里的情况也包括在内。
- **M10a′ 顾问**：
  - **配置**：三类用途接入现有的 `settings.resolve` 和载体模型发现，用户没单独配的就沿用默认值，不写死。
  - **记录**：每次调用记下实际用的载体、模型、推理强度，并绑定房号、问题 ID、计划版本。
  - **一题一轮**：每个问题只能调一次。
  - **记账**：用量按实际原生用量记进本房预算，只记一次；没拿到回执时标“用量待确认”，不记成零，也不自动重发。
  - **预算**：筹备期的调用也算进预算。
  - **用量口径**：房间预算改成按“本房执行 + 顾问调用”统计，不再用成员的累计用量（会混进成员在其他任务里的用量，也会漏掉助手当领头时的用量）。
- **M11′ 入口**：放在最左常驻竖条里「Leader」入口的下面。两种状态同时成立时，「等你定」优先于「作战中」。旧的多个房可以逐个进入；没有进行中的房时，入口能打开历史。

### 画布

- **M12′ 共用画布层的分工**：
  - **共用层负责**：相机、屏幕坐标和世界坐标的换算、指针捕获、手势仲裁、缩放锚点、取消。
  - **两张图自己负责**：命中对象、能不能编辑、拖动预览、放手提交、取消回滚。
  - **各自保留**：架构图的框选、连线、归属、版本历史；导图的托盘、排序、换父节点、转换。
- **M13′（替代 M13）手势**：浏览器分不清纯竖向的触摸板滑动和鼠标滚轮，所以统一规定：
  - 普通滚轮 / 双指滑动是平移，Ctrl+滚轮 / 捏合是以指针为中心缩放；
  - 设置里给一个“鼠标滚轮缩放”选项，两张图共用；
  - 右键短按出菜单，拖过一段距离才算平移；
  - 编辑模式下，鼠标在空白处是框选；
  - 触屏在空白处是平移；
  - 第二根手指按下或指针被取消时，撤销还没提交的拖动。
- **M14′ 导图坐标**：节点坐标是可选的。没有坐标的节点继续自动布局，拖动后只固定被拖的节点（或明确选中的子树）。连线、命中判断、适配视图都用最终坐标。换父和移动用同一个版本提交。点「恢复自动排列」才清掉手动坐标。
- **M15′ 独立 leader**：两种旧数据都要显示：没有位置记录的，和有记录但 `domain_id=NULL` 的。坐标、拖入 part（会顶掉原来的负责人资格）、拖出时的落点、架构版本回滚，都要在同一个操作里保持一致。

### 其他

- **M17′ / M23′ md 报告**：
  - 提交时 `document_md` 和 `document_html` 二选一；两个都传就拒绝，并说明原因。
  - 最终校验、CLI、MCP、草稿预览、存储读取、守则都要一起改。
  - md 按保存时的格式走可信渲染（`html:false`），由阅读器提供主题色和两款字体；只给 md 这条路放开字体加载。html 报告现有的隔离和资源边界保持不变，共用的 CSP 常量不改。
  - 验收要实测四件事：字体真的加载出来、主题能切换、旧的 html 报告仍能打开、旧报告里的图表照常显示。
- **M18′ 会话库**：
  - **系统管理员**：`project=NULL`，在任何工作区筛选下都单列显示。
  - **「待接入」**：只列外部会话和未分组人员。
  - **执行历史**：服务端保留执行的去重，禁止接入执行历史。
- **M19′（替代 M19）线程来源**：
  - **记来源**：每条原生绑定都记下来源，按 `(runtime, native_id)` 存：
    - 「Crew 创建」：在成功 `thread/start` 时记；
    - 「用户接入」：在接入的事务里记。

    旧数据只有能对上创建或接入证据的才回填；来源不明的保持原状，不归档。
  - **新建**：Crew 建的所有持久线程都用 `mcp` 来源，包括执行线程。
  - **旧的内部线程**：空闲时归档，续用前先解档。归档和恢复共用同一把运行租约，按精确的 native ID 操作。
  - **补扫**：只处理有归属证据、已停止、没人占用的线程。
  - **已知限制**：旧线程被续用期间，仍可能出现在桌面版里。
- **M21′ Git 管理员回帖**：只能回复本工作区里**实际通知过它**的原帖。可以通知原作者，但不能借 `to`、`*` 或正文里的 `@` 叫醒别人。直接调工具和通过 `crew_call` 调用走同一个校验，不开放 `channel.consume`。
- **M22′ 顶部标签**：后台把对话未读和交流区未读拆成两个计数。快照过期时，不再显示“正在推进”。
- **M24′ 新手引导**：用户选的开局方式要带进实际打开的工作区；取消选文件夹后能回到引导继续；回调重复触发也只创建一次。
