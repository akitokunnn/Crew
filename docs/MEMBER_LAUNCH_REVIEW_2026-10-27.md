# 成员重复启动复核（2026-10-27）

## 现场与根因

用户报告的成员「声纹无门槛」由 Claude Code 派给 Codex。只读核对正式实例后确认：桌面 EXE 为 0.2.39，后台使用所选 HOME 下的内容缓存，相关启动、目标、Codex 驱动源码与本次主干基线 bb83194 一致。开发主目录有其他任务的未提交改动，本次修复在独立工作树完成。

2026-10-27 日本时间 15:27:32，普通 `spawn` 为成员总对话创建了 Codex 原生线程并提交任务；15:27:52，目标分配又为同一成员建立了目标执行，并提交了同一实验的要求。两段日志均进入 working。两个 Codex 原生线程 ID 不同，但使用相同的稳定 Crew 成员 ID，工作目录也相同。这是两条实际开工链路，不是原生子代理被误识别。

根因是启动锁按总对话 ID / 目标执行 ID 分别生效，目标派工没有检查成员总对话已经在施工。既有测试覆盖同一会话的并发唤醒、恢复与独立目标并行，没有覆盖“普通 spawn 已开工，再 goal assign --start”的组合。新增回归在修复前对 Claude / Codex 均稳定失败：未抛出冲突，第二个执行被启动。

另外复现了原生身份唯一性的缺口：总对话与目标分别有唯一约束，但没有跨表检查；并发绑定同一个原生 ID 时，两个写入都能成功。这是本次复核发现的另一项缺陷，不作为上述现场的已确认原因。

## 自动化与验收边界

新增 GitHub Actions：每个 PR 和 main 推送运行完整 Python、网页 JavaScript、桌面单元测试，以及工作区和对话路由的隔离 Electron 交互验收。测试只使用临时 HOME、临时端口与假载体，不调用真实模型。新增回归进入默认 unittest discovery，并直接加载构建后的 backend 复验。

首次在干净 runner 运行又发现两项测试环境依赖：假进程的 CLI 名称解析仍依赖开发机安装的载体；Windows 短路径 TEMP 与产品解析后的长路径被断言为不同字符串。现在 ShellFixture 显式提供假载体解析，CI 只在规范化后的私有临时目录运行。短路径问题已本地复现（autostart 三项失败），换为规范路径后同组 11 项全部通过，不以安装真实 AI 或跳过断言来解决。

完整 runner 检查进一步覆盖到 Git 管理员的独立夹具，已共用同一假载体解析；身份环境变量在测试进程删除，避免把空字符串当作真实执行 ID。PowerShell 管道输入与同一 shell 直启原生解释器逐字节对照，覆盖不同宿主的 UTF-8 前导标记；损坏 Git 标记的断言对照当前 Git 的原始错误及退出码，避免依赖某一版本的英文措辞。隐藏窗口截图让 Chromium 的 capturer 生成真实页面帧，仍检查非空 PNG，不显示正式窗口或跳过交互。各独立验证步骤在其他测试失败时仍执行，使后端、网页、桌面及交互的失败能在同一轮暴露，整体仍按失败处理。

本次未停止、重启或更新正式 Crew，未写正式数据库。交付版本为 0.2.40，具体测试结果、PR 与产物校验信息随交付记录提供。测试覆盖以上已识别的操作路径，不能将测试数量表述为产品正确率，也不能据此宣称所有未来重复请求都能按语义去重。
