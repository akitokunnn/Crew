# 模块整理与验收清单

本清单保留用户要求的完整范围。局部模块拆分完成不代表整个整理目标完成。勾选项必须有对应实现和当前验收证据。

## 需要达到的状态

- [ ] 对话工作区的面板状态、布局、焦点、遮挡与样式集中在独立模块，应用入口不再重复维护。
- [ ] 前端功能动作有可扩展的登记和分发入口；新增模组不继续扩大集中式动作条件链。
- [ ] 压缩等异步 UI 状态有独立拥有者，并保留真实后端结果与键盘 / 鼠标差异。
- [ ] HTTP 请求按功能模块组织，路径、作用域和准入策略只有一份登记。
- [ ] HTTP 传输与业务操作分别管理，领域模块不依赖 `web.Service`。
- [ ] 会话历史、载体协议、进程生命周期、更新准入具有明确接口；目标运行不反向依赖聊天入口。
- [ ] 后端剩余后台协调、消息投递、状态投影和数据入口的职责经过审查；实际存在的集中耦合被处理，保留项有具体理由。
- [ ] 静态资源登记与发布共用一个模块，新增 UI 资源不再同步手工 Python 白名单。
- [ ] 桌面、前端、应用、领域、存储、原生载体的依赖方向有代码约束与模块地图。
- [ ] 新 UI 与后端功能模组有与实际实现一致的接入示例，后续 AI 有明确施工规则。
- [ ] README 与开发指南反映实际 UI、代码入口和验证方式，旧说明不再指导错误施工。
- [ ] 已有成员开工防重与身份归属修复正常整合，新增准入不因模块迁移丢失，并复验相关 CI。
- [ ] 关键模块可直接测试，关键旅程使用真实后台和假载体；现有功能回归、隔离交互和构建验收完成。
- [ ] 最终 diff、提交、正常 PR 合并及主干包含关系已核实；源码、产物与正式运行状态分别说明。

## 当前工作

本分支正在分别实施前端工作区、功能请求、会话运行和资源目录模块。尚未通过集成验收的部分保持未勾选。用户明确把任务调度与并发规则留待后续细聊，本轮仅整理职责、保持原行为并保留已确认的修复。
