| PostgreSQL 静态关系契约 | 81 张表、261 组外键，父表、列、类型和 UNIQUE 匹配 |

可选 SQL 契约校验命令是 `python docs/storage-v2/verify_sql_contract.py`。它需要仅供校验的 `pglast`；本次工具放在被忽略的临时目录，通过 PYTHONPATH 提供，没有增加应用运行依赖。PostgreSQL DDL 由 `python docs/storage-v2/generate_postgres.py` 从当前 SQLite 领域结构重现，测试会检查生成文件没有落后于来源。

完整包参考验证确实生成、重读并重建了含数据库与 HTML 文件字节的包，并确认另一工作区和本机凭据引用未被带入。参考工具仅用于已接受基线、明文、小型合成夹具；没有实现未同步 overlay 物化、云授权、加密或正式导入切换。

## 尚未进行的验证

本机没有运行 PostgreSQL 服务。因此没有执行实际建库、真实数据库角色与 RLS、函数及触发器运行、并发 CAS、租约争抢、数据库宕机恢复或对象存储集成测试。语法和静态外键检查不替代这些验证。

设计阶段尚未接入的本地 Repository、工作区打开流程和导出导入，已由本目录的[本地实现说明](implementation.md)描述。账号登录、云同步、真实 PostgreSQL/RLS 和云租约仍未实现或验证。

## 实施必须保留的闸

1. 新结构和旧数据先在暂存区转换，关联、数量、可读消息与文件摘要核对通过才切换入口。
2. 开工作区时识别并提示接续旧历史；撤掉启动时静默扫描并导入所有旧目录的路径。
3. 已接受领域状态、离线提议、审计和同步收据分清；不以本机乐观 revision 冒充云端已接受版本。
4. 恢复历史不恢复执行权或通知投递；跨机继续执行需要目录、工具、账号和有效租约检查。
5. 云端上线前补齐实际 PostgreSQL、角色隔离、网络中断、GC 与旧备份反例测试。
