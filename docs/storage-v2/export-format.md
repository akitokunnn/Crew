# Crew 完整工作区导出格式

本文件定义 `.crewpack` 的首版格式。它是应用数据交换包，支持离线保存、换电脑和灾难恢复；它不携带账号登录或运行中的进程，也不直接授予云权限。当前为设计契约，参考实现仅用于合成数据验证。

## 包结构

使用 ZIP 容器，内部路径固定为 UTF-8、正斜线和相对路径。

```text
example.crewpack
  manifest.json
  data.sqlite
  blobs/sha256/<64位小写摘要>
```

`data.sqlite` 只含领域结构、选定工作区和为维持外键所需的最小署名父记录。不得复制整个用户库再隐藏其他工作区；本地设备表、待同步队列、密钥引用、执行租约、机器路径和草稿均不进入包。历史中的消息原文可能自然包含路径，不能靠删路径破坏原话；机器可执行绑定必须排除。

ZIP 中不出现符号链接、绝对路径、重复文件名、`..`、Windows 盘符、非清单文件或活动 WAL/SHM 文件。导入有文件数、解压总量、单文件大小和压缩比限制，具体阈值由产品配额配置，不能无上限解压。

## manifest

`manifest.json` 至少包含：

| 字段 | 含义 |
|---|---|
| `format`、`format_version` | 固定格式名 `crew-workspace` 与包版本 |
| `schema_version`、`min_reader_version`、`min_writer_version` | 领域结构及最低读、写引擎版本；可读不等于允许接续写入 |
| `export_id`、`workspace_id` | 本次导出和原工作区的永久 UUID |
| `created_at` | UTC 导出时间，仅展示，不用作冲突胜负 |
| `consistency` | `complete` 或用户明确选择的 `metadata_only` |
| `source` | `local` 或 `cloud`；云端已确认的 epoch、deletion epoch 与 commit 水位，离线包也说明是否包含尚未同步的本地状态 |
| `database` | 固定路径、字节数、SHA-256 和每表记录数量 |
| `blobs` | 每个内容对象的摘要、字节数、固定包内路径 |
| `capabilities` | 是否含原生会话归档、选入的代码快照等；不宣称可恢复进程 |
| `omissions` | 明确未包含的对象及原因；`complete` 包必须为空 |

内容摘要用于检验字节完整性，不提供来源认证。攻击者可以同时改文件与摘要；云端签发的包可附签名和受信 key ID，导入仍需当前用户授权。加密导出需要独立版本化的加密封装与外部密钥，不将密码或解密密钥写在包里。第一版参考实现只验证未加密包，不冒充实现了加密。

## 导出事务

1. 固定领域数据库的一致性快照，记录云端 epoch、删除水位及是否存在待同步操作。普通包导出已接受基线；用户选择包含未同步编辑时，先在暂存区按依赖物化 Repository 提议并标记 `has_pending_changes=true`。导出不要求为了“完整”先把私有数据上传云端。
2. 选择目标工作区的所有领域记录；沿完整外键元组取得必要的父署名记录，不沿子关系带入同账号其他工作区的数据，也不携带个人设置或账号授权。
3. 对引用的不可变对象建立导出 pin，防止后台垃圾回收在打包期间删掉内容。文件变化必须生成新版本，不能原地修改同一个摘要对象。
4. 生成仅含目标闭包的新数据库，使用可信 DDL 建立结构，复制受允许的字段，执行外键和数据库完整性检查。
5. 检查引用对象均已完成、摘要和大小一致，并将对象字节写入包。完整模式中任何缺失均失败；不能静默改成仅记录模式。
6. 写入 manifest 并重新读取整个包校验。成功后才发布最终文件名，失败保留明确错误并释放 pin；不得留下一个看似成功的最终包。

正式实现按 `workspace_id` 索引分页投影记录、流式校验和写入对象，不将整账号所有记录或大文件一次读进内存。引用快照与 pin 的建立由存储层和 GC 共用的协调规则保护，不能在读取引用后、pin 生效前给 GC 留出删除窗口；压缩期间不长期持有全库写锁。参考实现有固定 64 MiB 合成包限制，并为了容易审查采用内存读取，不是大文件生产导出器。

导出包括报告与文档登记时保存的内容版本。未被登记为产物的代码、数据集、虚拟环境和临时文件不自动入包。需要携带时由用户选入快照，manifest 明确声明；它不是整台开发电脑镜像。

## 导入读取边界

包视为外部输入。先检查格式、清单、路径、大小和摘要，再将 `data.sqlite` 以只读方式打开；禁止加载扩展，不执行输入数据库中的触发器、视图、建表语句或迁移脚本。应用用当前受信 DDL 创建暂存库，仅从允许的实体表读取已知列，验证类型、版本和关联后写入暂存库。不得把包文件直接交给当前 `store.connect()`。

权限数据与署名数据分开。历史用户 ID 只用于说明谁曾发消息；导入包不能创建云端登录账户、邀请原成员、恢复机器人绑定或授予旧成员访问新账号。导入后权限由当前登录账号和云服务重新确定。

导入前提供实体数量、对象总量、来源设备的非敏感说明、目标工作区和冲突预览。记录可先只读打开，不要求恢复执行。暂存和校验通过前不得覆盖已有数据或把对象标记为可用。

## 三种操作

| 操作 | 身份及行为 |
|---|---|
| 只读查看 | 保留包身份，放隔离预览区；不取得云权限，不运行任务、不发通知 |
| 恢复原工作区 | 保留工作区和实体 ID，核对当前云 epoch、水位、权限、删除账本和本机状态后做受控恢复；不能用旧包覆盖新云状态 |
| 创建独立副本 | 为工作区及领域实体生成新 UUID，并使用完整映射改写外键和结构化引用；内容对象可按字节复用；历史署名保留、当前权限重新创建 |

复制模式需要处理所有领域引用，不只改 `workspace_id`。映射账本持久化于本次导入操作，重试复用同一映射，避免重复实体。原生会话 ID 和执行命令不作为可运行绑定导入；所有导入执行均无有效设备租约。

恢复模式不将整个快照当成一批“新增操作”推送云端。服务对原工作区执行恢复预检，保留较新的提交和删除事实；若冲突无法在业务规则下合并，要求选择只读查看、显式覆盖恢复或创建独立副本。覆盖恢复必须是独立、可审计的服务操作，不得借普通同步绕过冲突。

## 离线与删除

已经认识该工作区的设备，必须保留并检查已知的删除标记。未知新设备只拿到古老离线包时，无法知道云端后来发生的删除或权限撤销；这种包先进入只读隔离区，联网核对后才能恢复为现行工作区。用户仍可明确将它创建为新的离线副本，但不能自动沿用原云身份。

云端工作区删除使用 epoch 或等价的不可复用代际记录。删除的旧 ID 不因一份离线包重新出现就被服务器重新创建。活动快照、离线设备水位、备份和对象 pin 会影响清理时间；物理删除必须列出覆盖范围和预计保留期限。

## 原生工具接续

包保证 Crew 可读历史及保存的产物可携带。另一个电脑需要重新绑定代码路径和系统权限、安装并登录 CLI、检查项目依赖。原生归档只作为带工具及格式版本说明的可选内容；只有工具明确支持且验证成功时才能恢复原生会话，否则新建执行并载入可读交接材料。不能将云历史中的 `running` 显示为当前电脑正在运行。

## 校验反例

必须拒绝：缺失附件、内容摘要不符、重复 ZIP 路径、压缩包路径穿越、未知更新格式、同 ID 不同内容、跨工作区外键、夹带本机密钥或执行表、源文件在打包中变更且没有版本快照。验证失败时现有工作区和文件保持不变。

参考实现只覆盖已接受基线的明文完整包和关系闭包校验，不包含未同步提议物化、UI、云授权、加密、原生会话恢复或正式导入切换。其通过不能被表述为整个导入或同步功能已完成。
