# Crew 使用体验优化

依据：2026-10-28 对 0.2.42 正式前端的实际体验；用户授权自主设计、实现和体验迭代。产品需求保持 `CREW_PRODUCT_REDESIGN_2026-10-28.md`，接口保持 `CREW_API_CONTRACT.md`。

## 目标与设计判断

让第一次打开的人知道从哪里开始；让回来的人先找到需要处理的事；让执行中的人清楚当前对象、状态和下一步。保留米白／灰绿视觉基调，用明确层次和动作减少理解成本，避免靠继续增加留白来掩盖重复信息。

1. **首页与导航**：无工作区时就地引导选择文件夹；输入内容始终保留。已有工作时优先呈现带任务、工作区归属的待处理摘要。置顶常驻；同一任务在侧栏只保留一个主要入口，关联工作区在工作区页表达。工作区可收拢，长列表仍可浏览。工作区名称使用展示名。
2. **任务与成果**：开始／继续／停止整个任务清楚可见，模式单独表达。负责人、成员、成果和详情容易发现；详情默认阅读，编辑时才出现表单。新成果可直接查看，保留版本、恢复预览、持续报告及文件／网页入口。成员来历和返回路径始终明确。
3. **对话与拍板**：普通发送自然；排队及其他意图按需出现，并明确效果。保持当前回复停止与整个任务停止的区别。待拍板压缩重复层级，在原任务中沟通与答复。手机去掉键盘提示、保证触摸空间。任务／成员／文档切换保留草稿和阅读位置。
4. **设置、清单与旧功能**：用清楚的对象、来源和生效时间表达配置继承；各类提示词可看可改。TODO／灵感可扫读、可直接处理。统一工作台与工作区工具的导航语言，保留公共频道、Git、用量、历史、垃圾箱、待收编和完整设置。解决体验中发现的样例旧入口异常。

## 完成证据

用真实页面逐条验收：首次启动→添加普通文件夹→描述需求；回来查看待拍板与成果；任务→成员→负责人并检查独立草稿；明确开始／插话／排队／两种停止；阅读和编辑资料、恢复版本预览；TODO记下／开始聊／完成；三级设置和提示词；旧能力入口往返；PC及390px、深浅主题、窄屏菜单与键盘焦点。

此次为前端迭代，手工体验使用独立样例环境；现有 CI 继续负责真实 HTTP＋临时 HOME＋假载体的关键旅程，不在本机重复无关后台套件。绝不启动正式 AI 或写正式数据。界面与文案不新增快照、源码字符串或像素测试；仅在状态或路由行为变化时复用相关模块检查。必要CI及构建依仓库流程完成，不反复跑无关检查。

## 实现与实际检查

- 基线：main `82dbb3e`、桌面源码版本 `0.2.42`；分支 `codex/crew-ux-refinement`。没有改版本、打包或部署正式服务。
- 首页与导航、任务与资料、聊天拍板、设置和个人清单已实现；老功能补充工作台返回导航及统一名称。新增两份功能 CSS 已由正式 HTML 引用，删除被替代的任务输入框和旧首页样式。
- 桌面 1366×900、手机 390×844 实际操作：从首页新成果直达阶段成果；负责人输入草稿→成员→负责人后原文仍在且直接回对话；详情默认阅读，编辑后返回阅读仍提示有草稿；排队入口及其效果说明可见。
- 首次使用的 `scenario=empty`：输入需求→添加样例普通文件夹→进入新任务，需求保留。发现并修复新建样例任务首句重复；固定样例历史保留。
- 设置按“全局→工作区→具体成员”切换，编辑范围跟随对象；成员默认展示成员用途，并使用名字。手机个人清单与提示词实测无横向溢出，待办处理草稿跨页保留。
- 旧团队入口与工作台往返、深浅主题检查；修复样例旧入口轮询缺少 attention 等投影字段造成的异常。
- 已有功能检查覆盖任务／成果、聊天、设置、个人清单及客户端；新增仅限旧入口投影错误和设置对象语义回归。没有加入像素、源码字符串、样式快照测试。既有 CI 旅程只更新改变的操作入口，不扩测试范围。
- 实际体验再次修正：手机未展开待办不常驻显示三项操作；手机任务顶部减少约 29px；明确返回负责人时关闭资料抽屉；不同任务切换仍恢复其阅读上下文。添加工作区取消或离页后，晚到成功不会强行跳页或自动续聊。

## 集成边界

客户端继续使用共享接口说明中的现有接口，本次无接口字段或请求语义变更。桌面文件夹选择仅在已有桥接提供该能力时显示；普通浏览器填写执行电脑的路径。新前端源码可由正式后台直接发布，无额外前端构建。正式 Crew 未被重启、未写正式数据、未启动真实 AI；正式服务部署仍由后端／总集成负责人完成。
