# Mac 版与后台可选

决定日期：2026-11-19。用户逐条拍板，并对推荐方案回复"全按推荐"。本文记录第一版的范围、接口约定和分阶段做法；功能现状以代码和测试为准。

## 用户裁决（2026-11-19）

1. 要完整的 Mac 版，后台可以选择：本机后台，或局域网内其他设备上的 Crew 后台。Mac 本机也能当主机。Windows 版同样能选后台。
2. 只做局域网，不写死 ZeroTier；主机设置里把所有网口列成"地址 · 网口名称"，由用户自己选。
3. 连到别的设备时要完整 Crew。
4. 授权 30 天不用才失效，由被连接的主机管理；主机可以强制下线已连接的设备。
5. 只兼容 Apple 芯片。
6. 明显复杂的内容第一版不做（见下文"第一版不做"）。
7. 默认做法全按推荐：手动填主机地址并配对后记住，自动发现以后再做；Mac 要求自己装 Python 3.11+（Homebrew），找不到时明确提示；主机与客户端版本不一致时提示但允许连接；先做 Windows 上能完整测的"后台可选 + 主机端管理"，再做 Mac 移植和打包；Mac 上真实运行 Claude Code / Codex 由用户在自己的 Mac 上按清单试；无需 Apple 开发者账号，应用使用临时签名，不提交公证。首次将 Crew 拖入「应用程序」并双击，系统拦下后到「系统设置 → 隐私与安全性」的「安全性」一栏点「仍要打开」并确认（2026-11-19 按 macOS 15 规则更正）。

## 用户裁决（2026-11-21，Mac 实机试用后）

1. Claude Code / Codex 在 Mac 上也要一键更新，并和 Windows 一样可开关「空闲时自动更新」。已实现：识别 Homebrew cask（`brew upgrade --cask`，最新版本以 Homebrew 提供的为准）、npm 全局安装与 Claude 官方原生安装；更新前用 `ps` 确认没有进程在用这份安装，有则排队等待。
2. Crew 自己也要一键更新，Mac 和 Windows 都做；发布流程加上 Mac 的 dmg / zip（附 SHA-256）。设计经用户确认（全部按推荐）后已实现，见 [design-crew-self-update.md](design-crew-self-update.md)。

## 第一版不做

| 功能 | 原因 | 现状表现 |
| --- | --- | --- |
| Crew 自更新（远程主机） | 牵涉主机重启 | 远程只提示版本不一致；本机 Mac 和 Windows 的自更新已按 2026-11-21 用户裁决实现，见 [design-crew-self-update.md](design-crew-self-update.md) |
| 远程重启主机后台、远程系统管理员对话 | 主机后台不可用时远程无法连接 | 远程只读显示主机健康状态 |
| 远程导入 .crewpack、远程下载交接材料 | 需大文件上传 / 打包下载 | 在主机上操作；导出可远程下载 |
| 开机自启、Finder 右键菜单、锁屏自动转发通知（Mac） | 各需一套 Mac 机制 | 暂无 |
| 签名公证、自动发现局域网主机、Intel Mac | 用户裁决 | — |

原列在这里的“Codex 桌面交接 / 接回”和“在 VS Code 中继续”已于 2026-11-19 按用户裁决在所有平台删除（实际几乎没用、维护成本高），不再是待做项。

## 设备与授权（主机端）

- 设备分两类：`browser`（手机或电脑浏览器，沿用 cookie，能力仍按 `remote_routes.py` 白名单）和 `desktop`（Crew 桌面客户端，按设备令牌认证，拥有完整的人工操作能力）。
- 授权在最近一次使用后 30 天失效；每次认证成功（间隔不少于 60 秒落盘一次）同时顺延 `last_seen_at` 和 `expires_at`。浏览器 cookie 的 `Max-Age` 只作载体，失效以主机记录为准。
- 主机设置的设备列表显示类型、是否在线、最近使用时间；"强制下线"即撤销该设备，正在进行的连接随即断开，之后需要重新配对。
- 配对码仍只在主机本机生成。桌面客户端配对时 POST `/remote/login`，`kind` 为 `desktop`，主机在 JSON 里返回令牌，不写 cookie。
- 桌面客户端的所有请求带 `Authorization: Bearer <令牌>`，可以不带 Origin（浏览器跨源不能自行附加该头，且 POST 仍要求 `X-Crew: 1`）；带 Origin 时必须与 Host 一致。Host 校验不变。
- 桌面设备不能访问的接口：局域网访问管理、主机外壳管理（更新准备、连接切换、系统管理员对话与配置）、操作主机原生程序（打开 / 显示文件）、报告预览 worker、远程导入与交接材料、AI 内部接口。人工请求仍不能冒用 AI 身份字段。
- `/api/access/context` 返回三种来源：本机、桌面设备、浏览器设备，并给出 `local_controls`（Crew 设置与管理）、`local_desktop`（操作本机原生程序）、`host_admin`（主机自身管理，如局域网访问）。

## 主机文件夹与工作区（后台统一实现）

新建、打开已有项目、更改工作区目录、恢复历史时要选主机上的目录。原来由桌面外壳在本机 `fs` 上完成的目录检查、Git 根目录解析和建目录统一移到后台，本机与远程走同一套接口：

- `GET /api/projects` 为可写工作区附带 `directory_state`。
- `GET /api/host/folders?path=` 列出主机目录（只列文件夹），给远程选择器使用。
- `POST /api/host/workspace/existing`、`POST /api/host/workspace/new` 取代外壳里的 `existingWorkspace` / `newWorkspace`。

本机仍用系统文件夹对话框选路径；连到别的设备时用页面内的主机文件夹选择器。

## 桌面客户端（后台可选）

- 启动设置里后台可选"本机"或已保存的局域网设备；添加设备时填地址、配对码和设备名，令牌用系统安全存储（Windows DPAPI、macOS 钥匙串）加密后保存在启动设置目录，不放进任何 HOME。
- 连到别的设备时不启动本地后台；外壳的本地数据目录与所连主机的 HOME 分开。工作区标签加载主机地址，外壳为该地址的请求附加设备令牌。
- 首页按访问来源隐藏第一版不做的主机管理项，版本不一致时提示。

## 分阶段

1. 主机端：设备类型、令牌认证、30 天顺延、在线与强制下线、网口列表、桌面设备权限、主机文件夹与工作区接口。
2. 桌面外壳：后台可选、配对、令牌附加、首页远程模式；网页按访问来源显示。
3. Mac 后台移植：启动阻断、会话与进程、打开文件、网卡识别。
4. Mac 外壳与打包：窗口与菜单、PATH 与 Python、arm64 dmg、GitHub Actions macOS 构建。

每阶段完成后在 Windows 上验证并合入 live；Mac 上的真实运行由用户按试用清单验证。
