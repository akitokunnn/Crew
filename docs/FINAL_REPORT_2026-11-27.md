## 1. 一句话结论

**R0–R9 中除你裁决暂不做的 R4、R6 外都已完成，并合入集成分支。真实模型（Haiku 5.5 + gpt-6-luna low）跑通了场景 1–8，过程中发现的问题都已当场修完复跑。** 合入正式使用前你需要知道四件事：

1. **最终版本测试零失败**：最终提交 `32a647f` 上 Python 全量 2833 项全过（跳过 14）、前端 359/359、桌面 252 项（251 过、1 跳过）。性能在最终代码上复测过，空闲请求 3 → 0，切换 Leader、打开工作区都比改版前快（第 5 节）。
2. **用正式数据只读副本预演过迁移**：新版第一次打开正式库，crew.db 从 135 张表升到 148 张、加 117 个触发器，存储库 schema 3 → 4，约 1.1 秒，一次性；完整性检查通过，4 个工作区都能正常打开。
3. **大工作区第一次打开不再卡**：预演时发现真实大工作区（MIB_Project）第一次打开要等约 7.3 秒，已改成 Git 分支信息后台扫描、启动时预热；预热完成后第一次打开 129ms。服务刚启动 2 秒内就打开的话仍要约 1.6 秒（第 3 节“首次打开阻塞”）。
4. **冷启动比同条件下的旧版慢约 9%–13%**（新增模块加载），已接受。热请求、切换 Leader、打开工作区都比旧版快。

## 2. 怎么体验

- **首次启动迁移**：见第 1 节第 2 条。迁移只加表、加触发器、升 schema，不改已有数据；预演脚本 `Temp/rehearsal/rehearse.py` 只读复制正式库，不碰正式文件。

## 8. 你需要知道的风险与未覆盖之处

**会影响使用的**

1. **冷启动刚开始的 2 秒内打开大工作区仍要约 1.6 秒**（之后约 0.13 秒）。
2. **冷启动慢约 9%–13%**：同条件对比，新增模块加载所致。
