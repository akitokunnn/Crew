## 3. 关键契约、架构雷区与测试/截图命令（必看）

### 3.1 关键代码契约
1. **桌面端标签路由守卫（`desktop/src/tabs.cjs:116-126`）**：
   - `/notes.html` 与 `/assistant.html` 链接**绝对不能携带 `?query` 参数**（`!url.search`），否则 Electron 桌面端 `_destination()` 会判定为外部链接并用系统浏览器打开；只允许 `#hash`。
   - 工作区跳转使用标准形式 `/?project=<encodeURIComponent(name)>#...`（与 `tabs.cjs` `{ kind: 'project', name, hash }` 一致），总览页使用 `/`（无 query）。
2. **后端静态文件白名单（`plugin/crew/web.py:2045-2099`）**：
   - `web.py` 仅放行 `STATIC` 字典内显式登记的路径（同时通过 `remote_access.set_static_paths(STATIC)` 同步给局域网鉴权中间件）。
   - 任何新增或改名的 `frontend/` 静态文件，必须同步登记到 `web.py` 的 `STATIC` 及 `plugin/tests/test_assistant_http.py` 的 `test_new_page_assets_are_served_by_the_actual_backend`，且修改 `web.py` 后必须重启运行中的后端进程。
   - 仅修改 `frontend/*.css|js|html` 时，本地预览/测试服务每次请求会直接从磁盘读取最新文件（无需重启，除非改了 `web.py`）。
3. **VM 单元测试沙箱假设（修改前端共享函数前必核对）**：
   - `plugin/tests/test_runtime_ui.js`：通过 `vm` 注入切片函数测试 `app.js`，其中只伪造了 `CrewTheme: { logo: () => "" }`（无 `get`、`projectStyle`）、未加载 `global-rail.js`、`state.projects` 可能为 `undefined`，且明确断言当 `git_assistant === null` 且待处理数为 `0` 时侧栏 HTML **不得出现 `class="rail-badge"`**（因此工作区切换计数器务必使用 `.ws-count` 等独立类名）。
   - `plugin/tests/test_notes_ui.js`：在独立 `vm` 中加载 `assistant.js`，不加载 `global-rail.js`，调用需保持 `window.CrewGlobalRail?.update(...)` 可选链防御。
   - `plugin/tests/test_web_contract.py`：其中 `FrontendChannelContractTests` 4 条 `CrewBrowser is not defined` 失败为 `live` 基线既有问题（`test_web_contract.py` 未预先加载 `browser-utils.js`）。
4. **Spatial Studio 样式关键约束**：
   - **禁止在 `.main` 本身设置 `backdrop-filter` 或 `transform`**，否则会生成新 containing block，破坏内部 `#chat-head`、`position: fixed` 与吸顶工具栏滚动行为；仅在 `.head` / 浮层面板使用磨砂 `var(--studio-glass)`。
   - `:is(.app,body)>.sb` 使用 `z-index: 60`（高于 `#settings-surface` 的 `z-index: 55`），使设置展开时左侧栏与 `#workspace-popover`（`z-index: 80`）依然可交互且不被设置层盖住。
   - 关键样式变量定义在 `frontend/style.css` 尾部（`--studio-frame`、`--studio-sheet`、`--studio-glass`、`--studio-card`、`--studio-border`、`--studio-shadow-*`、`--codex-accent`）。
