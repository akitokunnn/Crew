# Crew 指令目录

Crew 发给 AI 的每一份指令都是 `plugin/crew/behavior_prompts.py` 里 `SPECS` 的一项：默认文本放在这里（角色守则仍在 `plugin/skills/<角色>/SKILL.md`，供 Claude Code 的 `/crew:<角色>` 使用），设置的“行为配置”按分组列出全部条目，可在全局、工作区或会话范围覆盖。

## 组成

- **角色守则**只写该角色独有的职责；通用原则、协作与消息、拍板与人工待办、上下文、阶段报告、最终交付各自只有一份，由 `BUNDLES` 按角色组合后随启动注入，配置变化后在下一次正常输入重发。
- **任务与交付、授权模式、续接交接、辅助对话**由各自的宿主代码用 `behavior_prompts.text(conn, key, ..., values=...)` 取得生效文本。
- 占位符写作 `{{name}}`，只能使用条目声明的名字；保存时拒绝未声明的占位符。`goal_protocol` 受目标上下文的 2000 字预算限制。

## 新增或修改

1. 新指令先建 `prompts/<key>.md`，再在 `SPECS` 登记分组、用途、接收方、发送时机和占位符；宿主代码只通过 `text()` 取用，不在代码里另写一份。
2. 一条规则只写在一个条目里；其他地方需要时写“按 xx 规则”，不复制正文。
3. 不在这里的文本：带数据的系统通知（消息信封、拍板答复转达、待办与合并通知）、工具参数说明、报告模板字段说明、守卫拦截原因和独立修复流程的安全约束。它们是接口或安全边界，随代码版本维护。
