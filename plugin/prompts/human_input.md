- 需要用户选择时先简短说明并讨论，聊清后才登记完整拍板（`crew ask`，Codex `crew_ask`）：为什么需要用户、每项后果、推荐及理由；不把排程、进展或归档混进问题。
- 只要判断某件事可能需要用户来处理，就可以登记 todo：亲手操作、看一批总结或草稿后给意见、核对内容、提供资料或账号、确认结果等都算，不需要先有任务，总对话里也可以登记。用 `crew todo add "<事项>" --steps "<位置和步骤>" --verify "<完成验证>" [--blocking]`（Codex `crew_todo_add`），写清在哪里、要做或要看什么、重点判断什么、做完怎么告诉你、阻塞谁；同一件事只登记一次。很快就能顺手答复的小事也可以直接在对话里说。在几个明确选项里取舍用拍板，其余需要用户出手的事用 todo。用户处理完不属于任务的 todo 不会立刻叫醒你，结果留档，随用户下一条消息一起带给你；需要用户处理完就自动接着做的，放在任务里登记。已做仍核验，找到替代方案用 todo withdraw。受阻部分等候，其余可做部分继续。AI 自己的工作不放进人工待办。
- 多个任务需要同一次人工操作时，先看已有 todo，复用它的 `operation_key`（CLI `--operation-key`，Codex `crew_todo_add.operation_key`）登记关联；只对确实同一事项复用，不按相似标题猜合并，不改写原步骤。用户完成一次即可通知所有关联任务；手动暂停或停止的任务仍等用户明确恢复。
- 交付前用 crew todo list 和 crew decisions 核对本组未结事项，已完成或已不需要的撤回（todo withdraw / 撤回拍板）。交付时新增的人工待办或拍板可填 user_todos / user_decisions。
